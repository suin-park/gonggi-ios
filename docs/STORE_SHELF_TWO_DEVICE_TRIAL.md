# 매장 기능 실증: 관리자 기기 등록 → 고객 기기 안내 (두 대)

상태: **구현은 되어 있으나 아래 절차는 아직 수행되지 않았다.** 이 문서는 사용자가 직접 수행할 검증 절차이며 결과가 아니다.
이 문서가 요구하는 서버(새 API와 테이블)는 **아직 어떤 서버에도 배포되지 않았다.** 배포 전에는 앱의 매장 기능이 「이 서버에서는 아직 사용할 수 없어요」로 표시된다.

## 0. 준비
| 항목 | 내용 |
|---|---|
| 서버 | `3d-locker` 저장소 브랜치 `feat/store-shelf-sync` 배포(스테이징 권장) + `prisma/migrations/2026_add_store_shelf` 적용. 운영 배포는 별도 승인 |
| 계정 | 플랫폼 관리자 1명(`User.role` ADMIN), 매장 담당자 1명, 고객 1명(담당자 아님) |
| 기기 | 관리자 기기 1대(LiDAR 없음: iPhone 14 Plus 가능), 고객 기기 1대(다른 기기, 같은 앱 빌드) |
| 앱 빌드 | `feat/store-shelf-record-entry` (개발 또는 TestFlight). 매장 메뉴는 DEBUG/TestFlight 빌드에서만 기본 표시(App Store 숨김) |
| 제품 | 20개 이상: 맛/용량 변종 3쌍 이상, 같은 제품 2곳 진열, 등록하지 않을 제품 5개 이상 |

## 1. 서버 쪽 설정 (관리자 토큰 필요)
```
POST /api/gonggi/admin/stores            { "name": "공기마트", "branchName": "강남점", "address": "서울 …", "latitude": 37.49, "longitude": 127.02 }
POST /api/gonggi/admin/stores/:id/managers { "userId": "<담당자 User.id>" }
```
- 담당자 권한은 이 API로만 만들어진다(앱에서 만들 수 없다).
- 확인: 담당자 계정으로 `GET /api/gonggi/stores/mine`이 매장을 반환하고, 고객 계정은 빈 목록이다.

## 2. 관리자 기기: 등록 → 게시
| # | 동작 | 확인 |
|---|---|---|
| 1 | 담당자 로그인 → 기록 탭 → 「매장」 → 「매대 기록하기」 | 담당 매장만 목록에 보인다. 고객 계정에서는 「매장」 섹션이 없다 |
| 2 | 매장 선택, 매대 양 끝 지정, 훑기, 통로 한 번 걷기 | 「찾은 제품」 증가 |
| 3 | 「촬영 끝내기」 → 검토(이름, 삭제, 합치기, 변종 확인) | 보정 횟수 기록 |
| 4 | 「저장하기」 → 「고객에게 게시하기」 | 「게시했어요 (v N)」 |
| 5 | 「제품에 3D 자산 연결하기」 | 맞는 카탈로그 상품을 직접 선택(자동 연결 없음) |

## 3. 고객 기기: 조회 → 안내
| # | 동작 | 확인 |
|---|---|---|
| 1 | 홈 탭 「매장 › 제품 찾기」 | 위치 권한을 거부해도 이름으로 선택 가능 |
| 2 | 「내 주변 매장 보기」 → 드롭다운에서 지점명과 주소 확인 → 선택 | 가까운 순서 |
| 3 | 「이 매장에서 제품 찾기」 | 게시본 내려받기(v N), 오프라인 사본 표시 |
| 4 | 카메라로 매대 쪽을 천천히 비춘다 | 「공간 맞춤 ✓」 (월드 맵 또는 기준 표지) |
| 5 | **새로 촬영한** 제품을 비추거나 「사진으로 찾기」 / 이름 검색 | 일치/불확실/미등록 구분 |
| 6 | 결과 선택 | 진열 위치(칸, 마지막 확인 시각), AR 마커/방향, 「직선 방향 안내」 또는 「통로 경로 안내」 |
| 7 | 연결된 제품이면 | 「3D로 보기」, 가능한 경우 「내 공간에 놓아보기」 |

## 4. 권한 검증 (서버)
- 고객 토큰으로 `POST /stores/:id/releases` → 403 `NOT_STORE_MANAGER`.
- 담당자 A 토큰으로 매장 B의 releases/publish/product-links → 403 (release ID를 바꿔 보내도 404/403).
- 게시 전 `GET /stores/:id/release` → 404 `NO_PUBLISHED_RELEASE`, `GET /stores`에 나타나지 않는다.
- 같은 검증은 `src/lib/store-shelf/service.test.ts`(16개)와 PostgreSQL 통합 테스트(3개)로 자동화되어 있다.

## 5. 검출 성능 측정 (실제 사진)
1. 진열대 사진 5~10장을 가로(센서) 방향으로 촬영한다. 밀집한 진열 포함.
2. 사진마다 제품 한 개당 박스 하나를 그려 JSON으로 만든다: `{"boxes": [[minX, minY, maxX, maxY], ...]}` (가격표, 매대 프레임, 포장 무늬는 박스에 넣지 않는다).
3. `GonggiTests/Fixtures/ShelfPhotos/<이름>.jpg` 와 `<이름>.json`으로 추가하고 `ShelfDetectionFixtureTests`를 실행한다. 출력 `SHELF_DETECTION_RESULT/TOTAL`에 검출률, 정밀도, 잘못 합치거나 나눈 비율이 나온다.
4. 기준(실증 전 고정): 검출률 ≥ 0.8, 정밀도 ≥ 0.7, 잘못된 분할 ≤ 0.15. 못 미치면 검출 모듈(`ShelfProductDetector`)을 교체한다.
- 사진이 없으면 테스트는 **건너뜀(skipped)** 으로 보고되며 통과가 아니다.

## 6. 측정 항목 (앱이 기록)
| 항목 | 위치 |
|---|---|
| 등록 시간, 보정 횟수 | 관리자 기기 `<매장>/metrics.json` registrations |
| 인식 정확도(맞음/틀림 버튼), 안내까지 시간, 안내 방식 | 고객 기기 `metrics.json` searches |
| 공간 복원 성공/실패, 시간 | `attempts.json` |
| 인식 임계값 보정 | `StoreThresholdCalibrator`(같은 제품/다른 제품 거리 쌍) |

## 7. 알려진 제한
- 인식은 Apple Vision 특징을 쓴다. 비슷한 포장의 변종 구분은 **측정 전**이며 부족하면 전용 검색 모델로 교체한다.
- 인식 모델 revision이 맞지 않는 기기에서는 이미지 인식을 끄고 이름 검색만 제공한다.
- 통로 경로는 관리자가 기록 중 걸은 길로만 만든다. 걷지 않은 구간과 다른 층은 안내하지 않는다.
- 실제 크기 AR 배치는 카탈로그 상품의 치수/모델 스케일 검증을 통과한 경우에만 표시한다.
