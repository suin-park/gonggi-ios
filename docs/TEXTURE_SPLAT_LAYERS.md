# 텍스처 스플랫 레이어 (실험 설계·검증 메모)

테스트_05(실기기 제품 촬영 125장, 3.0(23))의 같은 입력으로 PC 참조 구현(`research/product_tex`)에서 비교했다.
실데이터(사용자 사진·마스크·포즈)는 저장소에 올리지 않는다. 숫자는 PC/CPU 참조 값이며 A15·Metal 측정이 아니다.

## 비교 조건
- 입력: 테스트_05 연구 기록의 960×720 RGB, 포즈, K, 제품 마스크(Vision, 신뢰 123장). 평가 프레임 = 인덱스 % 10 == 5 (12장, 생성·깊이 정렬·최적화·노출 기준에 쓰지 않음, 가장 가까운 학습 시점 약 11 cm).
- 같은 고정 깊이(B/C/D/E): 인과 스테레오 앵커(서로소 참조 두 집합의 합의) + Depth-Anything-V2-Small(PC 모델, 앱의 Core ML 빌드가 아님) 역깊이 affine 정렬.
- 평가: 카메라 배경 OFF, 480×360, 제품(확실) 화소만. 노출 보정 PSNR은 모든 방법에 같은 채널별 이득을 적용.
- A_live는 실제 저장된 3.0(23) 지도이며 평가 프레임으로도 최적화되었으므로 held-out이 아니다(낙관적). A는 같은 현행 알고리즘을 PC에서 평가 프레임 없이 다시 돌린 인과 재현이다.

## 원인 분석 (실데이터)
- 교차 프레임 깊이 자기 일관성(같은 방법의 서로 다른 프레임 재투영): 중앙값 1.9~3.1%, p90 5.4~7.8%, p95 7~9%(1.35 m에서 중앙값 약 3~4 cm). 독립적인 거리 기준(LiDAR·자)이 없어 실제 깊이 정확도가 아니라 자기 일관성이다. 이 오차는 주름 깊이(수 cm)와 같은 크기다.
- C/D가 B보다 나쁜 이유: 서로 다른 프레임의 단일 시점 텍스처를 한 면에 굽고 간극을 메우는 방식이라, 깊이 오차만큼 텍스처가 어긋난 조각이 이어 붙는다(LPIPS 상승, 선명도 비율 1.9~3.0 = 가짜 고주파). 학습 시점에서 렌더해도 PSNR 20~22 dB에 그쳤다(다른 프레임의 조각이 섞임).
- 분할 끔 대조군: 분할 켬/끔 차이 없음(PSNR 20.39 대 20.39, LPIPS 0.248 대 0.248) → 분할이 화질을 올리지도 내리지도 않았다. 현행 구조의 뭉침은 분할이 아니라 점당 색 하나·큰 점 수·깊이 오차에서 온다.
- E가 좋은 이유: 각 키프레임이 자기 전체 제품 영역을 텍스처 레이어로 유지하고(조각을 서로 다른 프레임에서 섞지 않음), 새 시점에서 가까운 레이어 K개를 시점 방향 가중치와 깊이 일관성으로 혼합한다. 어긋남이 가까운 사진 사이의 작은 시차로만 나타난다.
- 깊이 융합(E2: 이웃 키프레임 깊이의 합의 중앙값)은 개선하지 못했다(PSNR 16.5 대 17.2, K=4). 재관측으로 형상을 개선하는 효과는 이 데이터에서 확인되지 않았다.

## 앱 구현 범위 (이 브랜치)
- 표현: 키프레임별 텍스처 서펠 레이어(셀 8×8 원본 화소 = 8×8 텍스처, RGBA8, 평면 사각형 4모서리), 영구 ID = (키프레임 ID, 셀 번호). 일반 3DGS PLY와 다른 형식이다(`.kmots`). 같은 형식이라고 약속하지 않는다.
- 렌더: 가까운 K개 레이어를 각각 그려 깊이 일관성으로 혼합(Metal), CPU 참조 렌더러와 같은 규칙.
- 저장·재열기·공유: 레이어·카메라·매니페스트 컨테이너. 카메라 배경 없이 다시 열어 돌려 볼 수 있다.
