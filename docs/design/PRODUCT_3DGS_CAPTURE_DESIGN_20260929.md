# 실물 제품 3DGS — 읽기 전용 설계 (2026-09-29)

범위: 설계만. 코드 수정, Pod, 재학습, 배포, TestFlight 없음. **"추정"** 표시는 측정 근거가 없는 값.

목표: iPhone으로 제품 주위를 돌며 촬영 → 배경이 제거된 실물 제품 3DGS → 받은 사람이 웹 링크에서 회전·확대.

## 1. 촬영 안내와 필요한 시점

- **시작**: 제품을 화면 중앙에 두고 탭 → ARKit raycast로 받침면(바닥/테이블) 위 중심점. 두 번째 단계에서 상자 크기를 손가락으로 맞추거나 LiDAR 메시로 자동 추정.
  이 상자가 (a) 궤도 커버리지 기준, (b) 마스크 생성의 3D 힌트, (c) 학습 후 잘라내기 범위가 됨.
- **궤도**: 방위 360°를 고도 3줄로.
  | 고리 | 제품 중심 기준 카메라 고도 | 방위 간격 | 장수 (추정) |
  |---|---|---|---|
  | 낮게 | 약 10–20° | 약 8–10° | 36–45 |
  | 중간 | 약 35–45° | 약 8–10° | 36–45 |
  | 높게(윗면) | 약 60–75° | 약 12–15° | 24–30 |
  합계 약 100–150장(추정). 앱 상한 520장보다 훨씬 적게 쓰므로 사진 수로 막을 일이 없음. 더 찍은 사진은 그대로 학습에 씀(사진 선별 없음 원칙 유지).
- **안내 UI**: 제품 주위 링에 방위 칸을 채우는 방식(기존 공간 안내의 "빈 영역 → 방향 안내" 규칙을 제품 중심 좌표로 바꿔 재사용). 거리 유지(제품이 화면의 약 40–70%), 너무 빠른 회전 경고는 기존 속도 기록 재사용.
- **바닥 면**: 1차 범위에서 **촬영하지 않음**. 받침면(ARKit plane)을 기준으로 그 아래 Gaussian을 잘라내고, 뷰어는 아래에서 올려다보지 못하게 고도를 제한(예: −5°까지, 추정). 접지 그림자는 촬영값이 아니라 뷰어에서 합성한 부드러운 그림자로 표시하고 그 사실을 명시.
  후속: 뒤집어 한 번 더 찍는 2회 촬영(두 세션 정합 필요 — 공간 설계서의 세션 간 정합 위험과 같은 문제).
- **뒷면**: 벽에 붙은 제품은 뒷면 칸이 채워지지 않음 → 촬영 전에 "벽에서 떼어 놓아 주세요", 촬영 후 결과에서 해당 칸을 "미촬영"으로 표시.
- **윗면**: 높은 고리. 키 큰 제품은 사용자가 팔을 올리거나 한 걸음 물러나야 함 → 윗면 칸이 비면 안내.
- Apple `ObjectCaptureSession`(iOS 17+, LiDAR 기기) 사용 여부: 안내 UI는 완성도가 높지만 기기 제한과 결과 파이프라인(사진·포즈 접근 방식)이 달라 **기존 ARKit 캡처 확장을 권장**. 필요하면 비교 실험 1회.

## 2. 배경 분리: 두 방법 비교

| | A. 전체 사진으로 포즈 → 마스크로 제품만 학습 (권장) | B. 사진에서 배경을 먼저 가린 뒤 전체 처리 |
|---|---|---|
| 카메라 위치 | 배경 특징점이 많아 COLMAP 안정(현재 공간 경로 그대로) | 무늬 적은 제품은 특징점 부족 → 등록 실패·오정합 위험 큼. ARKit 포즈로 보완 가능하나 정밀도 저하 |
| 학습 | FasterGS가 이미 `view.alpha`로 정답 이미지를 배경색과 합성하고 `USE_RANDOM_BACKGROUND_COLOR`를 지원 → 배경 영역은 투명으로 학습됨. NeRFICG COLMAP 데이터셋이 alpha를 읽지 않으므로 **데이터셋 어댑터(작은 호환 훅)만 필요** | 가린 이미지로 학습 시 가장자리가 검은/흰 테두리로 학습되기 쉬움 |
| 마스크 오류 영향 | 한두 장의 마스크 오류는 다른 시점이 보정(다시점 일관성) | 마스크 오류가 포즈와 학습 모두에 전파 |
| 잔여물 | 배경 Gaussian이 일부 남을 수 있음 → 받침면 아래·제품 상자 밖 3D 잘라내기 + 마스크 밖으로 투영되는 점 제거(FasterGS `CARVING_ENFORCE_ALPHA`와 같은 원리) | 배경 잔여 적음 |
| 비용 | 마스크 생성(GPU 1–3분, 추정) + 기존 COLMAP | 같음 + 등록 실패 시 재촬영 |

- 마스크 생성: 첫 사진의 탭 위치 + ARKit으로 투영한 3D 상자를 프롬프트로 영상 분할 모델(SAM 2 계열)이 전체 사진에 전파. 라이선스·모델 크기 확인 필요(워커 라이선스 게이트 대상).
- 그림자: 마스크는 제품만 포함(그림자 제외)하도록 → 받침면 그림자는 학습되지 않음.

## 3. 예상 실패와 사용자 품질 확인

| 상황 | 예상 실패 | 대응 |
|---|---|---|
| 제품 경계(털, 끈, 얇은 다리) | 마스크가 가는 부분을 잘라 결과에서 사라짐 / 배경이 섞인 테두리 | 마스크 경계 부드럽게(soft alpha), 얇은 구조는 1차 대상 제외 |
| 그림자 | 바닥 그림자가 제품 일부로 남음 | 받침면 기준 잘라내기 + 마스크에서 그림자 제외 |
| 반사(금속, 유광) | 시점마다 색이 달라 반투명 떠다니는 조각(floater), 비친 주변이 제품 표면에 박힘 | 1차 제외. 결과에 "반사 재질은 정확하지 않을 수 있음" |
| 투명(유리, 아크릴) | 마스크 정의 자체가 모호, 뒤 배경이 제품 안에 학습됨 | 1차 제외, 촬영 시작 시 재질 선택에서 경고 |
| 움직이는 제품(천, 반려동물, 손으로 돌림) | 흐림·이중상, COLMAP 불일치 | 제품은 고정, 사람이 도는 방식만 지원. 사진 간 재투영 오차가 큰 사진 수를 품질 지표로 기록(사진은 버리지 않음) |
| 무늬 없는 제품(흰 상자) | 제품 표면 특징점 부족 — A방식은 배경으로 포즈를 잡아 완화 | 무늬 있는 바닥/테이블 위에서 촬영 안내 |

사용자 품질 확인(생성 성공과 화면 품질을 분리):
1. **생성 성공**: 작업 완료, 등록 사진 비율, 마스크 적용 사진 수, Gaussian 수, 파일 크기.
2. **화면 품질**: (a) 턴테이블 미리보기(8방향 렌더 또는 짧은 영상), (b) 학습에서 뺀 확인용 사진 몇 장과 같은 시점 렌더 나란히 보기(NeRFICG `TEST_STEP`로 일부를 평가 전용으로 두는 방식 — 이 사진은 학습 대신 평가에 쓰인다는 것을 작업 기록에 명시), (c) 커버리지 링에서 빈 칸(뒷면·윗면·바닥 미촬영) 표시.
   수치(PSNR, 실루엣 IoU)는 내부 기준용으로 기록하고 사용자에게는 그림으로 보여 줌.

## 4. 제품 뷰어와 공유 링크

- 조작: 제품 중심 궤도 회전(한 손가락), 확대/축소(핀치, 최소·최대 거리), 평행 이동 제한(제품이 화면 밖으로 나가지 않게), 자동 회전(첫 진입), 고도 제한(바닥 미촬영 시).
  공간 뷰어의 걷기·비행 조작과 분리된 **제품 모드**. 시작 카메라 = 중간 고리 정면 사진 방향.
- 배경: 투명(임베드), 단색(공유 페이지 기본), 선택적으로 합성 접지 그림자.
- 공유 링크: 로그인 없이 열리는 `shareId` 기반 페이지(기존 공간 공유 구조 재사용), OG 이미지 = 턴테이블 첫 장, 다운로드 기본 꺼짐(`allowDownload`).
- 로딩 크기(추정, 근거: 공간 결과에서 Gaussian당 약 236 B 원본, compressed PLY 3.9배 감소 실측 256.9 MB → 66.7 MB):
  | Gaussian 수 | 원본 PLY (SH3) | compressed PLY |
  |---|---|---|
  | 200,000 | 약 47 MB | 약 12 MB |
  | 300,000 | 약 71 MB | 약 18 MB |
  | 500,000 | 약 118 MB | 약 30 MB |
  제품 상한 **300,000 Gaussian, 모바일 첫 로딩 20 MB 이하**를 1차 목표로 제안(추정). 현재 운영은 원본 PLY를 그대로 전송하므로 제품 공유에는 compressed 출력이 필수. SH 차수를 낮춘 더 작은 미리보기는 후속.

## 5. '실물 촬영'과 'AI 생성' 구분

현황: AI 결과는 `Asset`(`generationJobId`, `sourceAiModel`, `meshyAssetMeta`)로 저장되고 `/asset/[id]`, `/embed/[id]`에서 model-viewer(GLB)로 보이며, 이 페이지들에서 "AI 생성" 표시는 찾지 못함. 공간 3DGS는 `GaussianSpace`로 별도.

제안:
- 데이터: 결과마다 서버가 정하는 `provenance` = `captured`(실물 촬영) | `ai_generated`(AI 생성) + 근거(촬영 작업 ID·사진 수·촬영일 / Meshy 작업 ID·모델). 클라이언트가 바꿀 수 없음.
- 화면: 뷰어 위 고정 배지 — "실물 촬영 · 사진 132장 · 2026-09-29" / "AI 생성 · 사진 1장에서 추정". 공유 페이지·임베드·OG 제목·설명에도 같은 문구. 배지는 뷰어 설정으로 끌 수 없음.
- 혼합 금지: AI로 보정·채움한 촬영 결과가 생기면 별도 라벨("실물 촬영 + AI 보정")을 쓰고 `captured`로 표시하지 않음.
- 파일: 내려받는 PLY/GLB 메타데이터에도 출처 기록.

## 6. 최소 기능 검증

대상(무광, 단단함, 무늬 있음 — 반사·투명·털 제외):
1. **바닥에 놓는 소형 가구**(원목 스툴 또는 사이드테이블): 바닥 접지·다리 사이 빈 공간·받침면 잘라내기 검증.
2. **테이블 위 소품**(무광 도자기 화병 또는 운동화): 윗면·뒷면, 가장자리 품질 검증.

성공 기준(목표치는 추정, 첫 측정 후 조정):
- 생성: 제품당 5회 촬영 중 4회 이상 완료, 등록 사진 90% 이상.
- 배경: 8방향 턴테이블에서 배경·바닥 잔여물이 사람이 보기에 없음(평가자 2명 판정), 확인용 사진에서 실루엣 IoU 0.9 이상.
- 화질: 확인용 사진 대비 렌더 PSNR 25 dB 이상(추정 기준), 가장자리 테두리 없음.
- 공유: compressed 20 MB 이하, iPhone LTE에서 첫 화면 5초 이내(추정), 출처 배지 표시.
- 처리 시간 30분 이내.

작업량(1인 기준, 추정):
| 항목 | 일 |
|---|---|
| 앱: 제품 선택·궤도 커버리지 안내·패키지 종류 | 8–12 |
| 워커: 마스크 생성, alpha 데이터셋 어댑터, 제품 프로필, 3D 잘라내기, compressed 출력, 품질 지표·턴테이블 | 10–15 |
| 서버: 결과 종류·출처 필드·API·공유 페이지 | 5–7 |
| 뷰어: 제품 모드·배경·배지·로딩 | 5–8 |
| 검증(제품 2종 × 5회) | 3–5 |
| 합계 | 약 31–47 |

비용(추정):
- 제품 1건 GPU: 사진 100–150장 기준 COLMAP 5–10분 + 마스크 1–3분 + 학습 5–10분 + 압축·렌더 2분 ≈ 15–25분 → 약 $0.1–0.3(시간당 $0.3–0.7 가정).
  근거 참고: 운영 458장 COLMAP 658 s, 352장 격리 학습 722 s.
- 검증 10건 GPU 약 $1–3. 저장: compressed 약 20 MB + 원본 사진 약 70–100 MB/건.

## 7. 결정이 필요한 것
1. 결과 저장 모델: `GaussianSpace`에 `captureKind: object` 추가 vs 새 제품 모델(권장: 처리·권한을 공유하는 앞쪽).
2. 마스크 모델 선택과 라이선스.
3. 바닥 면 2회 촬영을 1차 범위에 넣을지(권장: 제외).
4. 출처 배지를 기존 Meshy 결과 페이지에도 소급 적용할지(권장: 적용).
