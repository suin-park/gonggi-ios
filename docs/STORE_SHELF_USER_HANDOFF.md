# 매장 기능 실기기 검증: 사용자용 요약

**연결 구성 (빌드 95부터)**: 로그인, 크레딧, 공간, 보관함, 카탈로그는 기존 운영 서버(`https://www.3d-locker.com`) 그대로입니다. 매장 기능(`/api/gonggi/stores…`)만 스테이징 서버(`https://3d-locker-staging.vercel.app`)를 호출합니다.
기존 계정으로 로그인하면 됩니다(재가입, 비밀번호 변경, 별도 테스트 계정 불필요). 스테이징은 앱이 보낸 운영 토큰을 운영 서버(`GET /api/auth/me`)에서 매번 확인하고, 이메일 문자열이나 앱이 보낸 사용자 ID는 믿지 않습니다.

## 권한
- **관리자**: `support@whiklab.com` 한 계정(운영에서 이메일 인증된 상태일 때만). 테스트 매장 전체의 생성, 등록, 수정, 게시, 3D 자산 연결.
- **그 외 모든 계정**: 매장에서는 고객(조회와 검색만). 다른 서비스의 역할(광고주 등)은 그대로.

## 1. 설치
1. TestFlight 내부 테스트에서 **2.0 (95)** 설치(기기 A: support 계정, 기기 B: 아무 고객 계정).
2. 기존 계정으로 로그인(앱을 한 번 완전히 종료했다가 다시 열어도 로그인이 유지되어야 한다).
3. 기록 탭 「매장」 섹션과 홈 「제품 찾기」는 TestFlight 빌드에서만 보인다.

## 2. 먼저 확인 (기존 기능이 그대로인지)
- 기존 보관함(공간 목록), 크레딧, 프로필이 평소와 같이 보이는가.
- 앱을 완전 종료 후 재실행해도 로그인 유지, 보관함이 그대로인가.

## 3. 준비물 / 촬영 방법
- 진열대 1개, 서로 다른 제품 **20개 이상**(맛/용량 변종 3쌍 이상, 같은 제품 2곳 진열 포함).
- 등록 때 쓰지 않을 제품 **5개 이상**(미등록 확인용).
- 기준 표지로 쓸 움직이지 않는 안내판 1개(선택), 실제 가로 길이(cm)를 재 둔다.
- 평가 사진: `docs/STORE_SHELF_EVAL_PHOTOS.md`.

## 4. 두 기기 검증 순서
**기기 A (support 계정, 관리자)**
1. 기록 탭 → 「매장」 → 「매대 기록하기」 → 매장 선택(「공기 테스트 마트 검증점 A」 또는 B).
2. 매대 앞면 양 끝 지정 → 천천히 훑기 → (선택) 기준 표지 등록 → 통로를 한 번 걷기 → 「촬영 끝내기」.
3. 검토에서 이름을 실제 상품명으로 수정, 잘못 찾은 제품 삭제, 같은 제품 합치기 → 「저장하기」 → 「고객에게 게시하기」.
4. 「제품에 3D 자산 연결하기」에서 「3단 라운드 마감장」을 아무 제품에나 연결.
5. 앱을 **완전 종료**했다가 다시 실행해 기록이 남아 있는지 확인.

**기기 B (다른 계정, 고객)**
1. 기록 탭에 「매장」 섹션에서 「매대 기록하기」가 **동작하지 않거나 매장이 보이지 않아야** 한다(고객 권한).
2. 홈 → 「매장 › 제품 찾기」 → 매장 선택 → 게시본 내려받기 → 매대 쪽에서 카메라를 천천히 비춰 「공간 맞춤 ✓」 확인(시간 측정).
3. 새로 촬영한 제품을 비추거나 「사진으로 찾기」, 이름 검색 → 일치/불확실/미등록 → 위치 안내.
4. 마커와 실제 위치 차이를 줄자로 잰다. 연결한 제품만 「3D로 보기」가 보여야 한다.
5. 앱 완전 종료 → 다른 자리에서 재실행 → 같은 제품 다시 찾기. 비행기 모드에서 「저장된 사본 (오프라인)」 확인.

## 5. 기록할 것
공간 맞춤 시간, 마커 오차(cm), 인식 정답 여부, 수동 보정 횟수, 불확실/미등록 처리, 재실행 후 복원 성공 여부.
