# 매장 기능 실기기 검증: 사용자용 요약

서버: 스테이징 `https://3d-locker-staging.vercel.app` (운영과 분리된 DB·프로젝트). 앱: 내부 TestFlight 빌드 2.0 (94).
이 문서에는 비밀번호가 없다. 계정 정보는 아래 "계정 전달"을 따른다.

## 1. 설치
1. TestFlight 앱에서 내부 테스트 빌드 **2.0 (94)** 설치(처리 완료까지 몇 분 걸릴 수 있다). 기기 두 대(A: 관리자, B: 고객) 모두 같은 빌드.
2. 이 빌드의 서버는 스테이징으로 고정되어 있다. 기존 운영 계정은 스테이징에 없으므로 아래 테스트 계정으로 로그인한다.
3. 기록 탭의 「매장」 섹션과 홈의 「제품 찾기」는 TestFlight 빌드에서만 보인다(App Store 빌드에서는 숨김).

## 2. 계정 전달
- 자격 증명은 파일로만 만들어졌다: `C:\Users\emili\Downloads\gonggi_staging_credentials.json` (채팅이나 저장소에는 없다).
- 항목: `managerA`(관리자 기기용, 매장 A 담당), `managerB`(다른 매장 담당, 권한 차단 확인용), `customer`(고객 기기용), `admin`(플랫폼 관리자, 앱에서 쓸 일 없음).
- 앱 로그인 화면에서 「이메일로 로그인」에 파일의 이메일/비밀번호를 입력한다. 검증이 끝나면 파일을 삭제한다.

## 3. 준비물 / 촬영 방법 (실사진 평가와 같이 쓸 수 있다)
- 진열대 1개, 서로 다른 제품 **20개 이상**(맛/용량 변종 3쌍 이상, 같은 제품 2곳 진열 포함).
- 등록 때 쓰지 않을 제품 **5개 이상**(미등록 확인용).
- 기준 표지로 쓸 움직이지 않는 안내판 1개(선택), 실제 가로 길이(cm)를 재 둔다.
- 평가 사진: `docs/STORE_SHELF_EVAL_PHOTOS.md` (등록 촬영 3~5장, 다른 날 새로 찍은 검색 촬영 3~5장).

## 4. 두 기기 검증 순서
**기기 A (담당자 A 로그인)**
1. 기록 탭 → 「매장」 → 「매대 기록하기」 → 담당 매장 선택(검증점 A).
2. 매대 앞면 양 끝 지정 → 천천히 훑기 → (선택) 기준 표지 등록 → 통로를 한 번 걷기 → 「촬영 끝내기」.
3. 검토에서 이름을 실제 상품명으로 수정, 잘못 찾은 제품 삭제, 같은 제품 합치기 → 「저장하기」 → 「고객에게 게시하기」.
4. (3D 확인용) 「제품에 3D 자산 연결하기」에서 스테이징 카탈로그의 「3단 라운드 마감장」을 아무 제품에나 연결해 본다.
5. 앱을 **완전 종료**했다가 다시 실행해 기록이 남아 있는지 확인.

**기기 B (고객 로그인, A와 다른 기기)**
1. 홈 → 「매장 › 제품 찾기」 → 「내 주변 매장 보기」(위치 허용 또는 거부) → 드롭다운에서 지점명과 주소를 확인해 「공기 테스트 마트 검증점 A」 선택.
   - 스테이징 매장의 좌표는 서울 임의 지점이라, 위치를 허용해도 멀리 있을 수 있다. 이름으로 선택하면 된다.
2. 「이 매장에서 제품 찾기」 → 게시본 내려받기 → 매대 쪽으로 가서 카메라를 천천히 비춰 공간이 「공간 맞춤 ✓」가 되는지 확인(시간을 잰다).
3. **새로 촬영한** 제품을 비추거나 「사진으로 찾기」, 이름 검색 → 일치/불확실/미등록 → 진열 위치 안내(마커, 방향, 칸 강조).
4. 마커 위치와 실제 진열 위치의 차이를 줄자로 잰다. 안내 방식(「직선 방향 안내」/「통로 경로 안내」)을 적는다.
5. 연결한 제품이면 「3D로 보기」, 「내 공간에 놓아보기」 확인. 연결하지 않은 제품에는 버튼이 없어야 한다.
6. 앱을 완전 종료 → 다른 자리에서 재실행 → 같은 제품을 다시 찾아 복원 시간과 오차를 기록. 비행기 모드에서 열어 「저장된 사본 (오프라인)」 표시를 확인.

**권한 확인(선택)**: 기기 B를 고객 계정으로 둔 채 기록 탭을 열어 「매장」 섹션이 없는지 확인. 담당자 B로 로그인하면 매장 A는 목록에 없어야 한다.

## 5. 기록할 것
공간 맞춤까지 걸린 시간, 마커 오차(cm), 인식 결과와 정답 여부(앱의 「인식이 맞아요/틀렸어요」), 수동 보정 횟수(검토 화면), 불확실/미등록 처리, 재실행 후 복원 성공 여부. 앱 안의 측정 기록은 매장 폴더(`metrics.json`, `attempts.json`)에 쌓인다.
