## 하지 않은 것
- 멈출 때 실제 사진 시점으로 자동 이동: 넣지 않음.
- 사진 전환 완화(가중 EMA): PC에서만 비교했고 앱에는 넣지 않음(현재 카메라의 결과가 이동 경로에 따라 달라지기 때문).
- V4를 기본값으로 쓰지 않음: PC에서 형태 손상이 확인됨(아래).

## PC에서 확인한 V4 부작용(test_10, test_09)
- test_10 16번(f000017.jpg): 자동 마스크가 판·받침 왼쪽을 25~37 px 빠뜨림(마스크 오류). 동시에 V4 판이 배경 쪽으로 열마다 약 14 px 두꺼움(V4 형태 오류). 이 사진에서 V4 윤곽 IoU 0.795 < 기존 Bm 0.811(수동 확인한 GrabCut 기준 윤곽).
- test_09(곰 의자): V4가 귀를 깎거나(58번) 팔 사이 오목한 곳을 채움(90번).
- V4는 레이어 화소의 약 74~78%에서 지도 깊이를 외곽 깊이로 바꾼다(외곽이 지도보다 중앙값 2.4 cm(test_09), 5.7 cm(test_10) 뒤). 채운 색은 윤곽의 중앙값 0.3%(test_09), 0.04%(test_10), 최대 3.4% / 14.7%.

## 기기에서 볼 것
- 기록하기 › 실험 › 제품 Bm 보기 → 저장본 선택.
- 처음 열기: 준비 화면 % · 단계 · 취소. 끝나면 '상세 진단'에 처음 준비 시간과 캐시 크기.
- 닫고 다시 열기 / 앱 완전 종료 후 다시 열기: '저장된 준비 결과로 열었어요'와 열기→첫 화면 시간.
- 기존 Bm ↔ V4 ↔ 반반을 같은 시점에서 비교. V4 줄에 채운 화소 %.
- 진단 저장·공유의 로그: `prepare_stage`(단계별 초), `hull_built`, `cache_written`(바이트·ms), `cache_open`(readMs), `cache_first_screen`(초), 프레임 시간(bm_*/v4_*), 메모리·열 상태.

A15 처음 준비 시간(특히 외곽 계산), 캐시 다시 열기 시간, 회전 반응, 메모리·발열은 기기에서 재지 않았다. CI 시뮬레이터(디버그)에서 합성 7장 결과의 캐시 다시 열기→첫 화면 0.96초, 합성 구 외곽(26만 칸 × 36장) 53초는 A15 성능 예측이 아니다.
