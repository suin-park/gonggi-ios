# 기록하기 › 실험 (센서 검사) — 사용 안내

이 도구는 **iPhone 14 Plus에서 센서·후면 깊이·ARKit 공존을 직접 검사하고 결과를 내보내는 검증 도구**입니다.
실시간 3DGS 생성·학습, 신경망 깊이, Metal 학습은 포함하지 않습니다.

## 어디서 여나
앱 하단 **기록하기** → 맨 아래 **실험 › 센서 검사**. 전체 화면으로 열리며 **닫기**를 누르면 기록하기로 돌아옵니다.
(이 메뉴는 빌드 설정 `GONGGI_SENSOR_EXPERIMENTS=YES`인 빌드에서만 보입니다. 정식 배포 빌드에서는 `NO`로 바꿉니다. 서버·DB·원격 설정은 쓰지 않습니다.)

## 메뉴
| 메뉴 | 하는 일 |
|---|---|
| 기본 센서 검사 | ARKit 추적 상태·위치·방향, 영상 해상도와 실제 FPS, 희소 특징점, 평면, 노출/EXIF, Core Motion 수신 빈도, 메모리, 열 상태. 옵션을 하나씩 켜서 부하를 비교(‘부하 비교’ 자동 5단계) |
| 후면 깊이 검사 | 듀얼 와이드 장치 발견 → 사진용 깊이 → 영상·깊이 호환 포맷 → 깊이 출력 연결 → **실제 깊이 콜백 수신**을 각각 구분해 표시. 영상+깊이를 `AVCaptureDataOutputSynchronizer`로 함께 받아 FPS, 드롭, 유효 픽셀 비율, 타입/accuracy/quality/filtering, calibration, 동기화를 기록 |
| 카메라 공존 검사 | ARKit 단독 / 후면 깊이 단독 / ARKit 후 깊이 / 깊이 후 ARKit. 구간별 실제 수신 빈도와 중단·오류로 **공존**을 판정하고, **동기화**는 따로 판정 |
| 실험 결과 | 실행 이력, 검사별 요약, JSONL 원본 공유 |

## 저장하는 것 / 하지 않는 것
- 저장: 숫자·상태 로그(JSONL)와 읽기 쉬운 요약(`*.summary.txt`). 위치: 앱 Documents/`experiment-logs/` (파일 앱에서 보임).
- 기본으로 저장하지 않음: 사진, 영상, 깊이 맵. **‘분석용 샘플 저장’을 켠 경우에만** 최대 10장·12MB의 JPEG(최대 640px)와 float32 깊이를 `*-samples/` 폴더에 저장합니다.
- 서버로 자동 업로드하지 않습니다. 공유 시트로 직접 보낼 때만 나갑니다.
- 한 검사의 로그는 8MB·6만 줄에서 멈추고, 넘긴 줄 수를 요약에 남깁니다.

## 실험 절차 (앱 안 ‘실험 절차’와 같은 순서)
1. **기본 센서 검사 60초** — 옵션 모두 끄고. 같은 장소에서 ‘부하 비교’도 한 번(정지 / 천천히 이동 각각).
2. **후면 깊이 검사 60초** — 단계 표시를 먼저 확인하고 ‘자동’ 포맷으로.
3. **0.5·1·2·3 m 표적 비교** — 무늬 있는 종이(A4 이상)를 벽에 붙이고 정면, 화면 가운데. 줄자로 **후면 카메라 렌즈에서 종이 표면까지 카메라가 바라보는 방향의 거리(camera-Z)** 를 재서 해당 버튼(‘표적 기록’)을 누릅니다. 화면 **가운데** 값만 씁니다(가장자리에서는 range와 Z가 달라집니다).
4. **무늬 있는 면 / 흰 벽 / 물체 경계 비교** — 같은 거리(1 m 권장)에서 각 20초 이상. 얇은 물체(의자 다리 등)도 포함.
5. **정지 vs 천천히 이동 비교** — 후면 깊이 검사를 각각 30초.
6. **공존 검사** — 먼저 ‘ARKit 단독’, ‘후면 깊이 단독’을 실행(기준 빈도), 이어서 두 순서의 공존 검사를 실행.
7. **기존 기록 기능 복귀 확인** — 실험을 닫고 기록하기에서 360 공간이나 3D 자산 촬영이 정상인지 확인.
8. **결과 공유** — 각 검사 끝의 ‘결과 공유’ 또는 실험 › 실험 결과.

## 숫자를 읽는 법 (오해하기 쉬운 것)
- **유효 깊이 픽셀 비율** = 값이 채워진(유한하고 0보다 큰) 픽셀의 비율입니다. **정확도가 아닙니다.** 여러 프레임에서 값이 일치해도 정확하다는 뜻이 아닙니다.
- **정확도**는 ‘표적 기록’의 줄자 기준 거리와 비교한 오차로만 판단합니다. 이 값도 해당 장면·거리의 값일 뿐입니다.
- 듀얼 와이드 깊이는 **disparity(상대 역깊이)** 로 올 수 있습니다. ‘변환값’(depth)은 변환일 뿐 accuracy가 `relative`이면 절대 거리 정확도가 보장되지 않습니다. depth 형식이어도 range(렌즈에서 점까지 직선)인지 camera-Z인지는 문서로 확정되지 않았습니다.
- 깊이·영상 버퍼는 **센서 방향 그대로**(회전·크롭·리사이즈 없음)이고 렌즈 왜곡이 반영된 상태입니다. 3D 점으로 쓰려면 calibration으로 정류해야 합니다.
- ARKit **sceneDepth는 LiDAR가 필요**해 14 Plus에서는 쓸 수 없습니다. 후면 듀얼 와이드 깊이와 별개입니다. 사람 마스크/깊이는 사람 영역 전용이며 공간 깊이가 아닙니다.
- 렌즈 상태(lensPosition, ISO 등)는 ARKit이 쓰는 캡처 장치를 **읽기만** 합니다(`configurableCaptureDeviceForPrimaryCamera`). **읽은 시각은 특정 영상 프레임의 촬영 시각이 아닙니다.**
- **공존 성공** = 함께 도는 구간에서 두 스트림이 실제로 계속 들어오고(단독 대비 70% 이상, 5 Hz 이상) 중단·오류가 0건. **동기화 성공**은 별개이며 영상 프레임 주기의 절반 이내(잠정 기준). 두 기준은 모두 잠정입니다.
- 한 순서에서 공존이 되었다고 반대 순서도 된다고 볼 수 없습니다. 두 순서를 모두 실행합니다.

## 안전장치
- 일반 검사는 카메라를 한 번에 한 화면만 씁니다(소유권 게이트). 의도적인 동시 실행은 공존 검사뿐입니다.
- 뒤로 가기, 닫기, 홈으로 나가기(백그라운드)에서는 세션·타이머·구독을 정리합니다.
- 열 상태가 `serious` 이상이면 자동으로 종료하고 요약에 이유를 남깁니다.
- 실행 시간 선택(30초/1/2/5분)과 항상 보이는 **중지** 버튼이 있습니다.

## 결과 파일 읽기 (PC)
```
python analysis/analyze_logs.py <복사한 .jsonl>     # 연구 폴더 gonggi-research/sensor-depth-probe/analysis
```
JSONL의 `kind` 값: `header`, `ar_support`, `phase_begin/end`, `ar`, `lens`, `hb`(1초 요약), `A_result`, `B_result`, `C_config`, `v`/`d`(프레임), `dstats`(깊이 통계), `cal`(calibration), `target_reading`, `coexist_phase_*`, `summary`.
(`analyze_logs.py`는 이전 프로브 앱 로그 형식을 대상으로 만든 것이어서 이 앱의 줄 이름과 일부 다릅니다. 앱이 만드는 `*.summary.txt`가 1차 요약입니다.)

## 실기기 검증 상태
이 문서와 앱은 아직 **iPhone 14 Plus에서 실행되지 않았습니다.** 센서 지원, 정확도, 공존 여부는 모두 미측정입니다.
