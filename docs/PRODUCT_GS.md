# 실시간 제품 3DGS (기기 내, 서버 없음)

기록하기 › 실험 › **실시간 제품 3DGS (기기 내)**. 고정된 제품을 휴대폰으로 비추는 동안 가우시안을 만들고, 다른 시점에서 비출수록 디테일을 개선하며, 이미 잘 만들어진 부분은 보존한다.
공간 실험(가우시안 최적화)과 같은 공통 엔진(`Gonggi/Experiments/GSOpt`)을 쓰고, 제품 전용 부분은 `Gonggi/Experiments/ProductGS`에 있다. 기존 제품 3DGS(서버 업로드 경로)·공간·Image-to-3D·센서 기능은 바꾸지 않았다.

## 사용자 흐름
대상 선택(탭) → 마스크 확인(초록 = 제품, 노랑 = 경계 띠) → 촬영 시작 → 실시간 생성·정밀화(가우시안만 표시) → 일시정지·둘러보기 → 이어서 촬영 → 종료·저장 → 저장본 재열기·공유 → (연구 기록이 있으면) 같은 입력 비교.
제품은 고정하고 휴대폰을 움직인다. 돌림판·손에 들고 제품을 돌리는 방식은 물체 포즈 추정이 없어 지원하지 않는다. 카메라 배경은 비교용 옵션이며 기본은 가우시안만 보인다.

## 기존 코드와의 관계
- 기존 제품 3DGS(`Features/ObjectCapture`): 촬영은 ARKit이지만 마스크는 서버(SAM2)에서 만든다 → 실시간 요건을 충족하지 못해 재사용하지 않았다. `Capture/ObjectCapture/ObjectProductSegmenter`가 쓰는 기기 내 Vision 전경 마스크(`VNGenerateForegroundInstanceMaskRequest`)와 같은 API를 프레임마다 돌린다.
- 공통 엔진 재사용: ARKit 입력, 스테레오 앵커 + 단안 깊이 정렬, 지속 지도, 희소 Adam, CPU forward/backward, Metal 렌더, 저장 컨테이너(`.kmogs`), 연구 기록(`.kmoreplay`).
- 제품 전용: 마스크 생성·추적, 마스크 손실, 3D 범위, 배경 억제, 제품 기준 검증, 정밀화 배분, 계산 예산, UI, 저장 폴더(`Documents/product-gs`).

## 마스크
- 대상 ID를 유지하며 시점마다 갱신한다. 직전 신뢰 마스크와의 겹침(IoU ≥ 0.35)과 면적 변화(0.3~3배)가 맞으면 같은 대상이다.
- 라벨: 제품(확실) / 배경(확실) / 불확실(경계 띠, 가림·흐림·추적 실패). 불확실은 RGB 감독에도 배경 억제에도 쓰지 않고, 제품 일부를 지우는 근거로도 쓰지 않는다. 신뢰할 수 없는 프레임은 가우시안 생성·감독에서 통째로 제외한다.
- 배경을 검게 칠한 영상을 정답으로 쓰지 않는다: 제품 화소만 RGB 감독, 확실한 배경은 알파를 0으로(`bgAlphaWeight`), 띠는 감독 없음.
- ARKit에는 전체 카메라 입력이 그대로 들어간다(마스크는 가우시안 쪽에만 쓴다).

## 3D 범위와 가우시안 생성
- 2D 마스크만으로 거리·부피를 정하지 않는다. 제품(확실) 안의 스테레오 앵커 점들로 견고한 상자(3~97 백분위 + 여유)를 만들고, 점 120개·서로 다른 시점 3개 이상이 모여야 확정한다. 확정되기 전에는 밀집 깊이가 앵커 깊이 중앙값의 ±35% 안인 화소만 쓰고 스테레오 확인이 없는(단안만) 가우시안은 키프레임당 300개까지만 만든다(임시 상태).
- 제자리 회전만으로는 독립 삼각측량 증거로 세지 않는다(이동 4 cm 이상일 때만).
- 확실한 배경 화소에 서로 다른 시점에서 반복 투영된 가우시안은 배경으로 표시되어 불투명도 하한이 −5까지 내려가고 투명해지면 제거된다. 3D 범위 안의 안정 가우시안은 마스크 오류일 수 있어 세지 않는다.

## 최적화·검증·롤백
- 깊이 손실은 기본 OFF, 앵커 화소의 알파 항 0.1(투명화 회피 방지), 불투명도 하한 logit −1.5(제품 가우시안), 배경 표시 가우시안만 −5. 3.0(21) 방식(옛 깊이 항 0.8, 하한 −4)과 새 깊이 항은 같은 입력으로 비교한다(`GSOptProductCompareTests`).
- 갱신 전후 같은 고정 검증 시점(최근 + 과거)에서 제품 화소 L1·실루엣(제품 화소 평균 알파)·배경 누출·깊이 일관성과 **고정 고해상도 창(원본에서 직접 자른 192×144)** 의 RGB·경계 오차를 비교한다. 저해상도 평균만으로 판정하지 않는다.
- 분할·ID 발급까지 검증에 포함한다. 악화하면 파라미터·Adam 모멘트·step·revision·상태·독립 증거·정밀화/분할 누적·분할 자식·ID 발급 기준을 함께 되돌린다. 분할로 위치가 바뀐 부모·자식은 후보 상태·독립 증거 1회로 낮추고 새 관측으로 다시 올린다. 분할은 후보 이상·관측 3회 이상·배경 표시/의심 없음일 때만 한다.

## 원본 고해상도
- 센서 원본(이 기기 설정에서는 1920×1440, 실제 크기는 로그에 기록)에서 직접 960×720 영상을 만들어 JPEG로 메모리에 보관하고, 정밀화·검증 창(192×144)을 거기서 잘라 쓴다. 축소 영상을 키운 영상을 쓰지 않는다. 창의 K는 주점을 창 원점만큼 옮긴다. 창 크기와 원본 해상도를 로그에 각각 남긴다.
- 정밀화 창 배분: 4번 중 2번 오차 우선(이미 많이 한 칸은 감점), 1번 아직 정밀화되지 않은 칸, 1번 가장 오래 갱신하지 않은 칸. 진행률(제품 칸 수·갱신된 가우시안 수)은 검증을 통과한 정밀화만 센다.
- 메모리 캐시(`GSOHiStore`)와 연구용 디스크 기록은 분리되어 있다. 연구 기록을 꺼도 정밀화는 같다.

## 계산 예산 (A15에서 계측하도록 로그에 남김)
- ARKit 추적 주기는 그대로, 새 깊이·지도 추가는 최대 초당 3회(키프레임 간격 ≥ 0.33 s), 화면 렌더 30 fps 목표(렌더 FPS는 생성 속도·화질이 아니다).
- 최적화는 한 시계 초에서 쓰는 시간 비율 상한(0.5, 부하·열이 있으면 절반)과 반복 수 × 가우시안 수 상한(240k)을 둔다. 설정한 계획 시간과 실제 실행 시간의 차이를 `gso_opt` 로그와 요약에 남긴다. 열 제한 시 정밀화·최적화 중지·재개를 화면과 로그에 표시한다.

## 저장·재열기·공유
- `Documents/product-gs/product-gs-<runId>.kmogs` (+ PLY/상태/메타/요약, 연구 기록 ON이면 `.kmoreplay`). 공간 결과(`gaussian-opt/space-gs-*`)와 폴더·이름이 겹치지 않는다.
- 매니페스트: 제품 중심, 3D 범위, 좌표계(ARKit 세계 좌표, y 위, m), 스케일 의미(ARKit 포즈 기준 추정, 치수 정확도 미검증), 미관측 안내, 정밀화 진행, 관측한 방향 커버리지, 마스크 통계. ID·상태·계보·외관은 저장 → 재열기에서 같다(테스트로 확인). 카메라 영상 없이 가우시안만으로 돌려 볼 수 있다.
- 연구 기록 ON: 960폭 RGB(JPEG q0.9)·마스크(KPM1)·포즈·K·시각·노출을 용량 상한(400 MB, 600장) 안에서 이 기기에 저장한다. 자동 업로드는 없고 공유 시트로 직접 보낼 때만 나간다. OFF면 요약과 저장 목록에 "재생 자료 없음"이 표시된다.
- 사용자 사진·영상·지도·카메라 좌표·재생 캐시는 공개 저장소에 커밋하지 않는다.

## 검증 범위 (구분)
- 단위/합성 테스트(CI 시뮬레이터, CPU 래스터): 마스크·추적·범위·손실·게이팅·롤백 복구·정밀화 배분·검증 창·저장 왕복·연구 기록 왕복·같은 입력 비교 행렬.
- 실기기 전용(미측정): Vision 마스크 품질·지연, A15 속도·열·메모리, 실제 제품 화질, 단안 모델 정확도.
