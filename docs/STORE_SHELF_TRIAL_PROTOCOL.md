# 매장 기능 실증 절차: 20개 제품 전체 흐름 (iPhone 14 Plus)

상태: **구현은 되어 있으나 빌드와 실기기 실행은 아직 하지 않았다.** 이 문서는 사용자가 직접 수행할 검증 절차이며 결과가 아니다.
이 절차를 수행하기 전에는 "자동 등록 완료"로 보고하지 않는다.

## 빌드 상태
- 순수 로직(`Core/`): Swift 5.9 Linux에서 45개 테스트 통과 (`Tools/StoreShelfLogicCheck/run.sh`).
- Apple 프레임워크 계층(ARKit, Vision, RealityKit, SwiftUI): **컴파일하지 않았다.** macOS CI(승인 필요)나 Mac에서 빌드해야 한다.

## 사전 준비
1. 개발 빌드 또는 TestFlight 빌드를 iPhone 14 Plus에 설치한다(이 브랜치의 빌드는 아직 만들어지지 않았다).
2. 진열대 1개와 **서로 다른 제품 20개 이상**을 준비한다. 다음을 반드시 포함한다.
   - 같은 브랜드의 맛/용량 변종 3쌍 이상(예: 콜라와 제로)
   - 같은 제품이 두 곳에 놓인 경우 2개 이상
   - **등록하지 않을 제품 5개 이상**(미등록 확인용)
3. 매대 앞에 여유 공간(통로)이 있고 조명이 일정해야 한다. 매대 앞면이 바닥과 만나는 선이 보여야 한다.
4. 선택: 움직이지 않는 안내판 1개(기준 표지).

## 절차
| # | 동작 | 기록할 것 |
|---|---|---|
| 1 | 기록 탭 → 「매장」 → 「매대 기록하기」, 새 매장 만들기 | 진입 가능 여부, 하단 탭바 가림 여부 |
| 2 | 매대 앞면 한쪽 끝에 맞추고 「여기가 매대 한쪽 끝」, 반대쪽 끝에도 | 지정 실패 메시지 여부 |
| 3 | (선택) 「기준 표지」로 안내판 등록 | 표지 인식 메시지 |
| 4 | 매대를 좌→우, 칸마다 천천히 훑는다 (제품 하나당 약 2~3초) | 화면의 「찾은 제품 N개」 |
| 5 | 매대 앞 통로를 따라 한 번 걷는다 | |
| 6 | 「촬영 끝내기」 → 검토 화면 | 자동으로 찾은 제품 수, 저장하지 못한 영역 수, 확인이 필요한 제품 |
| 7 | 이름 수정, 잘못 찾은 제품 삭제, 같은 제품 합치기, 변종 확인 | **보정 횟수**(앱이 기록) |
| 8 | 「저장하기」 | 등록 시간(앱이 기록) |
| 9 | **앱을 완전히 종료** → 기기를 다른 위치로 이동 → 앱 실행 | |
| 10 | 기록 탭 → 「제품 찾기」 → 같은 매장 | 공간 맞춤 상태와 걸린 시간 |
| 11 | **등록 때 쓰지 않은 새 촬영**으로 제품을 하나씩 비춘다(손에 든 제품 또는 사진으로 찾기) | 결과(일치/불확실/미등록), 맞는지(「인식이 맞아요/틀렸어요」) |
| 12 | 안내 시작 후 매대 칸까지 걸어간다 | 마커 위치 오차(cm), 안내 방식(직선/통로 경로), 안내까지의 시간 |
| 13 | 3~12를 다른 시간대/조명/위치에서 반복 | 회차별 |

## 측정과 판단 기준 (실증 전 고정, 결과를 본 뒤 바꾸지 않는다)
| 항목 | 측정 | 기준(초기 가설) |
|---|---|---|
| 등록 시간 | `metrics.json` 등록 기록의 시작~저장 | 매대 1개 ≤ 5분 |
| 수동 보정량 | 보정 횟수 ÷ 저장 제품 수 | ≤ 0.2 |
| 제품 구분 정확도 | 검증 버튼 기준 맞음 ÷ (맞음+틀림), 변종/미등록 별도 | 20개 제품 중 ≥ 80%, **미등록을 기존 제품으로 확정한 건수 0** |
| 위치 오차 | 안내 마커와 실제 칸/위치의 차이(수동 측정) | 올바른 칸 ≥ 80%, 중앙값 ≤ 10 cm |
| 공간 복원 성공률 | `attempts.json` 복원 성공 ÷ 시도 | ≥ 80% (45초 안) |
| 검색→안내 시간 | 검색 기록의 시작~안내 시작 | ≤ 20초 |

## 임계값 보정 (필수)
- 일치/불확실/미등록 판정 임계값(`ShelfMatchConfig`)과 같은 제품 판정 임계값(`ShelfProductGrouper.Thresholds`)은 **보정되지 않은 초기값**이다.
- 이 데이터로 보정하려면 같은 제품을 다른 각도에서 찍은 쌍의 거리와 다른 제품 쌍의 거리를 기록해 `StoreThresholdCalibrator`에 넣는다. 분리되지 않으면(`separable == false`) Vision 특징만으로는 부족하다는 뜻이며, 전용 검색 모델(PP-ShiTuV2/DINOv2 변환)로 `ShelfAppearanceExtractor`를 교체한다.

## 알려진 제한
- 제품 검출은 사각형과 전경 분리를 쓰므로 둥근 병, 파우치, 반사 포장, 매우 빽빽한 진열에서 누락될 수 있다. 누락된 영역은 「저장하지 못한 영역」에 집계되며, 다시 가까이서 촬영한다.
- 위치는 매대 앞면 평면 위에서만 추정한다. 평면 앞뒤로 깊이 놓인 제품의 위치 오차는 포함되지 않는다.
- 통로 경로는 사용자가 기록 중 **걸어간 길**과 기록된 매대 영역으로만 만든다. 걷지 않은 구간은 경로로 안내하지 않고 「직선 방향 안내」로 표시한다.
- 안내는 저장된 진열 위치이며 현재 재고가 아니다.
- 한 번 기록하면 앱을 삭제하기 전까지 기기에 남는다. 서버 동기화는 없다(기기 간 공유 불가).

## 실패 시 복구
- 공간 맞춤 실패: 「다시 맞추기」로 재시도하고 저장된 매대 사진을 보며 기록할 때 비춘 쪽으로 이동한다. 계속 실패하면 기준 표지를 비춘다. 그래도 안 되면 「매대 기록하기」에서 「기존 기록을 지우고 새로 시작」한다.
- 인식이 불확실: 후보 사진에서 직접 고르거나 「사진으로 찾기」를 쓴다.
- 등록이 누락됨: 검토 화면의 「더 촬영하기」로 같은 세션에서 이어서 훑는다.
