# 텍스처 레이어 표면 정합 (테스트_07 분석 · 3.0(26))

기준: TestFlight 3.0(25), SHA 70d28eb58830. 브랜치 `feat/surface-align`. 실기기 영상(후반 8.5~11.5초)에서 눈·코 중복, 팔걸이·등받이가 층으로 갈라짐, 거친 윤곽이 보였다.
**아래 수치는 PC 참조 구현(Python)과 CI 단위 시험 결과다. 새 빌드의 실기기 측정은 없다.** PC 깊이(Depth-Anything-V2 HF 모델을 960×720 원본에 돌려 스테레오 앵커에 맞춤)는 앱의 Core ML 깊이와 다르다.

## 1. 원인 (확인한 것 / 확인하지 못한 것)
| 항목 | 결과 |
|---|---|
| 좌표·K·픽셀 중심·단위 | 재생 자료 로더와 빌더의 규약이 일치(K는 원본 폭 비율로 환산, 화소 중심은 정수 좌표, 깊이는 ARKit m). |
| 카메라 포즈 | 인접 프레임 쌍의 에피폴라(Sampson) 오차 중앙값 약 1 px(960 기준), 간격 3 쌍은 중앙값 1.7 px. 최악 쌍 14.7 px는 대응점이 적은 흰 의자 특징 때문일 수 있어 포즈 오류로 단정하지 않는다. |
| 레이어 간 형상 불일치 | 저장본 레이어 j를 레이어 i의 카메라로 그린 깊이 차 중앙값 1.8 cm(id 간격 1) → 3.7 cm(간격 4). 시점이 벌어질수록 커진다. |
| 외부 CPU 진단 재검증 | 6개 시점 · 시점 점수 상위 5개 레이어 쌍의 제품 내부 깊이 차(20 cm 미만 쌍) 중앙값 1.6~4.9 cm(평균 3.2). 외부 진단 2.8~7.9 cm와 같은 자릿수이며 앱의 최대 8개 선택이나 실제 거리 오차는 아니다. |
| 렌더러 vs 깊이 | 합성 정답 장면에서 **정확한 깊이를 넣으면 고스트가 없고**(고주파 상관 0.55), 앱과 비슷한 깊이 오차(중앙 1.4 cm)를 넣으면 0.25로 떨어진다. 고스트의 원인은 합성 규칙이 아니라 레이어마다 다른 3D 위치다. |

## 2. 구현 (Swift, 기기 내, 서버·LiDAR·학습 없음)
- **사진 정합** (`TexLayerAlign.swift`): 셀을 자기 카메라 광선 위에서 깊이 s배(0.85~1.15)로 옮겨 보며 이웃 레이어 사진에 재투영한 16×16 창의 ZNCC를 비교. 이웃 중 최선 둘의 평균, 3×3 셀 합산, 포물선 보간. 질감이 없거나 비용이 높은 셀은 믿지 않고 주변 값을 퍼뜨리며, 3×3 중앙값·가우시안으로 평활. 그다음 이웃이 같은 광선에서 가리키는 표면 깊이(±10 %, 2개 이상)의 중앙값 쪽으로 **절반만** 이동하는 교차 합의 1회.
- 사각형을 카메라 중심 기준 균일 배율하므로 레이어는 자기 사진을 그대로 재현하고 **텍스처는 바이트 단위로 같다**(시험 확인). 정답으로 믿는 깊이는 없다.
- 시점: 촬영 중 새 레이어마다(작은 탐색) → 종료 시 전체 한 번 → 정합 정보 없는 저장본(3.0(25) 이하)은 열 때 메모리에서만 정합(파일 불변).
- 저장: 레이어 파일(TSL1)은 그대로(모서리가 정합된 위치). `align.bin`에 셀별 누적 배율을 두어 모서리 ÷ 배율로 **원본 복원 가능**. 이전 앱 판은 align.bin을 무시한다.
- 둘러보기: 저장본 시작 시점을 앱 기본(pitch 11.5°)이 아니라 실제로 관측한 촬영 시점(사각형이 가장 많은 레이어)으로. 회전 범위는 제한하지 않는다. `*.browse.jsonl`에 가상 카메라·선택 레이어·렌더 크기·관측/불일치/미관측 칸·제외 표본을 0.25초 간격(움직일 때만, 900 KB 상한)으로 기록(숫자만, 사진·마스크 없음). 공유 묶음에 포함.
- 윤곽: 마스크 띠 반경 2→1, 마스크를 쌍선형으로 늘린 부드러운 텍셀 알파, 경계 셀 포함(제품 비율 ≥25 %), 알파 0.5 미만 텍셀의 색을 같은 셀의 가까운 완전 텍셀 색으로 연장(배경색 번짐 방지).
- 선택 전환: 가중치 0.25초 크로스페이드, 가중치가 가장 큰 레이어의 5 % 미만인 레이어는 합의 개수에서 제외(CPU·Metal 동일).

- 보류 프레임은 완전한 held-out(레이어 생성·정합·노출 연쇄에서 제외)이며 PC 깊이 기준이다. 일부는 노출/포화(채도 약간 증가)와 섞여 있다.
- 저장본(앱 깊이) 정합 효과: 이웃 레이어 깊이 차 간격 1: 2.04→0.98 cm, 간격 4: 3.75→2.22 cm. 6개 시점 5레이어 차 평균 3.2→1.5 cm.

## 4. 대조 실험 (현재 후보 채택 판단)
1. **조각남**(합성 정답 장면, 같은 레이어·카메라·선택, ≥2 동의 규칙만 켜고 끔): 정답 표면 안에서 규칙으로 지워진 비율 1.3~2.0 %, **선택된 레이어 어디에도 표면이 없는 비율 10.8~12.8 %**(시점 11.5·30·54° 평균). 구멍의 대부분은 미관측/가려진 면이다. 규칙을 끄면 구멍이 2 %p 줄지만 고주파 상관 0.310→0.294, 바깥 조각 0.012→0.015로 고스트·조각이 늘어 **채택하지 않는다(규칙 유지)**.
2. **크로스페이드**(저장본 정합 후, 0.75°/프레임, 8프레임): 프레임 간 평균 |Δ밝기| 0.0134→0.0110(54°), 0.0145→0.0125(11.5°), p95 감소. 54°에서 최댓값은 0.0211→0.0265(1회 튐)로 오른다. 서로 다른 깊이는 합성 단계가 가중치 최대 깊이만 쓰므로 섞이지 않고, 5 % 미만 레이어 제외는 시험(CPU 단위 시험)으로 확인.
3. **한 바퀴 후 재방문**(실제 재생, 보류 프레임 5·15·45 = 시작 구역): 첫 구역 레이어만 22.43 dB → 한 바퀴 뒤 전체 레이어 26.80 dB(정합 시 23.21→27.96). 선택을 첫 구역으로 제한하면 26.50로 같은 수준. **재방문으로 기존 구역이 악화하는 증거는 없다.** 단, 포즈 드리프트는 측정하지 않았고(복잡한 포즈 최적화는 이번 범위 밖) 개선이 확인되지 않은 재관측으로 기존 레이어를 바꾸는 처리는 넣지 않았다.

## 5. 남은 문제
- 시점 11.5°(앱 기본)·측면에서 팔걸이·좌판 윗부분이 조각나 보인다. 원래 관측이 없는 면이 대부분이고(이전에는 겹친 복사본이 이를 가렸다), 규칙 완화는 고스트를 되살려 채택하지 않았다.
- 한 의자·한 번의 촬영, PC 깊이 기준. 앱 Core ML 깊이로 정합한 결과, 속도·발열·메모리(A15), Metal 실제 화질은 **미측정**.
- 정합 비용: PC(numpy)로 레이어 1장당 약 1초이며 앱 비용은 미측정(기기 예산을 위해 촬영 중에는 작은 탐색 12×이웃 4, 종료 시 전체).
- 포즈 드리프트·루프 클로저 보정 없음.

- 빠른 CI(fdad3db, macOS 시뮬레이터): 컴파일 통과. `GSOptTexLayerTests` 20개, `GSOptTexLayerPipelineTests` 5개, `GSOptTexLayerGPUTests` 통과 — **Metal↔CPU 일치 IoU 0.986, 44.5 dB**(크로스페이드·합의 개수 변경 후). `TexLayerAlignTests` 11개 중 10개 통과, 1개(합의 개수 시험)는 시험 단언이 잘못(지운 화소의 합의 개수는 0)이어서 단언을 고쳤다. 전체 빠른 CI 93개 중 실패는 이 1개뿐이었다.
