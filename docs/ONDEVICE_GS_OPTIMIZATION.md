# 기기 내 가우시안 최적화 (기록하기 › 실험 › "가우시안 최적화 (기기 내)")

iPhone 14 Plus(A15, LiDAR 없음)에서 **서버 없이**, 촬영하는 동안 가우시안을 만들고 **기기 안에서 반복 최적화**하는 실험 경로다.
기존 V1(가우시안, 3.0(19)) / V2(표면 패치 + 사진 투영, 3.0(20)) / 서버 3DGS / Image-to-3D / 센서 검사는 그대로 있다.

## 무엇이고 무엇이 아닌가

- 사전학습 깊이 모델(Depth Anything V2 Small, Core ML)은 **기기 내 추론만** 한다. 가중치를 재학습하지 않는다.
- 가우시안 파라미터(위치·log-scale·쿼터니언·색·불투명도)는 **촬영 중 반복 최적화**한다. 이것은 장면별 최적화이며 "완전 무학습"이 아니다.
- 촬영 후 별도의 긴 학습을 요구하지 않는다. 종료하면 현재 상태를 그대로 저장한다(종료 후 숨은 최적화 없음).
- 표시와 저장은 실제 가우시안이다. V2의 불투명 패치/원본 사진 투영은 이 경로의 렌더링에 쓰지 않는다. 카메라 영상은 비교용 토글일 뿐이다.
- ARKit 카메라 포즈는 고정이다(최적화하지 않는다).

## 데이터 흐름

```
ARSession(하나) → 같은 ARFrame의 RGB·포즈·K·시각·노출 (SV2Input; ARFrame을 쥐지 않음, 대기 1)
  GSOPipeline.process (지도 큐 한 곳)
    1. 320폭 RGB → 훈련 해상도 160×120 (노출 정규화: 프레임 평균 밝기만 사용, 지도 색을 쓰지 않음)
    2. 스테레오 앵커: V2의 다중 시점 평면 스윕(과거 키프레임만 참조) + 역방향 일치 + 불확실성. 강한 표본만 앵커.
    3. 단안 깊이(Core ML) → 앵커에 강건하게 affine 정렬 (역깊이/깊이 두 가정을 모두 맞춰 더 맞는 쪽을 선택·기록)
       앵커 수·공간 분포·내부점 비율로 신뢰도를 낮추고, 부족하면 단안 깊이를 쓰지 않는다(스테레오 전용으로 대체).
    4. 삽입: 현재 지도를 이 시점에서 렌더해 누적 α < 0.6인 곳(설명되지 않는 영역)과, 앵커 깊이보다 앞이 비어 있는 곳에만 새 가우시안.
       깊이 경계는 만들지 않는다. 단안 전용은 temporary, 스테레오 앵커 위는 candidate에서 시작.
    5. 증거: 스테레오 앵커 깊이와 일치하는 가우시안의 독립 지지(카메라 ≥4cm 또는 시선 ≥3.5° 이동)를 센다. 독립 3회 → stable.
  GSOPipeline.optimizeSlice (키프레임 사이사이, 예산·거버너 준수)
    최근 4개 키프레임 + 과거 1개(재방문이면 현재와 시선이 비슷한 과거 시점) 중 하나를 골라
    CPU forward → 손실(Charbonnier 광도 + 스테레오 앵커 깊이/알파) → CPU backward → 희소 Adam
    (색·불투명도 먼저, gradient를 6번 받은 뒤 위치·크기·회전). 크기/위치 경계, NaN 건너뜀, 묶음 단위 롤백.
  게시(0.25초): GSOMap → RTSplatSet → V1 Metal 렌더러(rt_vertex/rt_fragment) — 화면은 실제 가우시안만
  저장: .kmogs(가우시안 파라미터·ID·상태·관측 이력·revision·계보 + 훈련 카메라 + 매니페스트) + 호환 PLY/.state + meta/summary/JSONL(runId 연결)
```

## 최적화 구현

| 항목 | 내용 |
| --- | --- |
| forward | 타일(16px) 래스터라이저, 깊이순 over 합성. V1 셰이더와 같은 의미(EWA, +0.3px² 팽창, 마할라노비스² > 9 제외, α < 1/255 제외) |
| backward | 해석적 gradient: 위치·log-scale·쿼터니언(정규화 포함)·색·불투명도, 렌더 깊이·누적 α 채널 |
| 검증 | 유한차분과 대조(PC 기준 구현과 Swift CI 모두). PC 기준: 모든 파라미터 최대 오차 ≤ 0.06%(최대 gradient 대비) |
| 표시 경로 일치 | CI 시뮬레이터 Metal에서 앱의 `rt_vertex/rt_fragment` 출력과 CPU forward를 비교(PSNR은 CI 로그) |
| 파라미터화 | log-scale, 정규화 쿼터니언, 불투명도 logit(0.99·sigmoid). 처음 값 주변 경계(크기 −0.7/+0.5 log, 위치 3×처음 크기) |
| 최적화기 | 희소 Adam(gradient를 받은 가우시안만). lr 색 0.012, 불투명도 0.04, 위치 2e-4, log-scale 1e-3, 쿼터니언 5e-4 |
| 왜 CPU backward | Metal 래스터라이저의 backward는 타일별 원자 누산이 필요하다. A15에서 float atomic 경로를 검증하지 못한 채 구현하지 않고, 먼저 검증된 CPU 경로를 연결했다. GPU backward는 미구현이다. |
| 예산 | 묶음당 최대 8회/45ms(열 fair 이상·AR 24Hz 미만이면 4회+60ms 간격, serious/메모리 1.9GB 이상이면 최적화 중단, critical은 자동 종료) |

최적화하지 않는 것: 포즈, SH 차수(RGB/SH0만), 분할/복제(삽입과 제거만).

## 같은 입력 A/B/C 비교

- A: 기존 V2(표면 패치 + 원본 사진 투영)를 같은 입력으로 만들어 같은 시점·해상도에서 렌더.
- B: 밀집 깊이 + 가우시안, 최적화 끔(초기화·삽입만).
- C: B와 같은 입력·모델·전처리·깊이 초기화·삽입 규칙 + 최적화 켬. (Cc: 색·불투명도만 최적화)
- 평가 프레임은 인덱스 % 10 == 5로 고정하고 생성·정렬·최적화·키프레임 선택에 쓰지 않는다(포즈·K만 렌더 카메라). 시점 t까지 도착한 프레임만 쓴다.
- 전체 화면 PSNR/SSIM, 가우시안 면적(α ≥ 0.5), 구멍(α < 0.1)을 함께 낸다. 지원 화소만의 PSNR은 보조다.
- 앱 안: 가우시안 최적화 화면 › "같은 입력으로 A/B/C 비교"(V2 저장본 또는 연구 기록).

## 한계

- 평가 지표는 영상 유사도이며 실제 거리 정확도가 아니다.
- 포즈 오차(ARKit)는 그대로 들어간다. 세그먼트(추적 복구·재개)는 서로 병합하지 않는다.
- A15 속도·열·실사 화질, 실제 Core ML 모델의 출력 의미(역깊이 가정)는 실기기 전에는 미측정이다.
- 훈련 해상도가 160×120이라 표시 해상도에 비해 가우시안이 크다.
- 재방문 시 과거 시점이 최적화 창에서 차지하는 비율이 작아 오래된 영역의 품질이 시간이 지나며 떨어질 수 있다(PC 기준 구현에서 관찰, 아래 결과 참고).

## PC 기준 구현의 재생 결과 (테스트_03의 178장, 이 PC, A15 아님)

`research/ondevice_gs/`(numba CPU 래스터라이저 + 같은 알고리즘의 파이썬 구동기). 평가 프레임 17장(인덱스 % 10 == 5)은 깊이 참조·정렬·색·최적화에 쓰지 않았다.
깊이는 PC 대역(평면 스윕 앵커 + Hugging Face Depth-Anything-V2-Small → 앱의 Core ML 변환본과 같다고 가정하지 않는다)이고 재생 입력은 V2 저장본의 JPEG(손실)다.
훈련 해상도 160×120, 삽입 간격 2, 키프레임당 24회 반복(PC 측정, 반복당 약 10~20ms).

| 변형 | 전체 화면 PSNR | SSIM | 면적(α≥0.5) | 구멍(α<0.1) | 비고 |
| --- | ---: | ---: | ---: | ---: | --- |
| B 초기화만 | 16.10 | 0.455 | 99.4% | 0.36% | |
| Cc 색·불투명도만 최적화 | 17.54 | 0.548 | 99.3% | 0.35% | B 대비 +1.44 dB |
| C 전체 최적화(과거 시점 1) | 17.64 | 0.614 | 98.1% | 0.01% | B 대비 +1.55 dB, SSIM +0.16 |
| C 과거 시점 2 (앱 기본) | 17.59 | 0.668 | 98.0% | 0.02% | SSIM +0.21, 도착 시점 PSNR 19.8 |

- 시간대별 최종 PSNR(early/mid/late): B 15.7/16.1/16.5, C(앱 기본) 17.3/15.7/19.8. **최종 지도에서 일부 구간(중간)이 B보다 낮다.**
- 평가 프레임이 도착한 시점의 지도로 잰 PSNR(도착)과 끝난 뒤(최종)의 차이: C 19.4 → 18.1 (같은 프레임). 뒤 시점 최적화가 앞 구역을 약간 해친다(과거 시점 재생을 늘리면 SSIM만 개선).
- 최악 프레임: C 9.9~10.7 dB(창 쪽 파란 하늘이 번진 청색 안개). 좋은 프레임만 고르지 않았다. 비교 이미지: `Downloads\gso_research_20261019\results\heldout_montage_target_B_Cc_C_Cpast2_160x120.png`.
- 색 변화에 경계를 두는 변형(±0.3)은 17.37/0.654로 오히려 낮았다(채택하지 않음).
- ablation(256×192): 스테레오 깊이 제약 끔 17.33/0.629, 켬(가중 0.4) 17.00/0.627, 낮은 lr+가중 0.8 17.40/0.623, 반복 48회 16.74/0.643.
- 형상 최적화가 켜진 C는 SSIM이 가장 높지만 PSNR 이득은 Cc와 같은 수준이다: 이 입력에서 **형상 갱신의 PSNR 추가 효과는 증거가 없고 SSIM(구조)에서만 개선**이다.

## 실기기에서 5분 확인하는 방법

1. 기록하기 › 실험 › "가우시안 최적화 (기기 내)" › 연구 기록(재생용 원본 입력 저장) 켜고 시작.
2. 책상·소파 같은 한 구역을 옆으로 천천히 이동하며 비추고, 같은 구역을 다른 위치에서 한 번 더 비춘다. 5분 정도 촬영 후 종료·저장.
3. 화면 진단의 확인 항목: 모델 준비 여부, 정렬 내부점/신뢰, 최적화 반복/초, 손실 변화, 롤백, 열·메모리, 표시 지연(출처 present/gpuEnd).
4. 저장 직후 화면이 저장본을 다시 연 화면이다. "결과 공유"로 한 번에 보내고, "같은 입력으로 A/B/C 비교"에서 방금 기록한 입력으로 A/B/C를 기기에서 돌려 결과 텍스트를 공유한다.
