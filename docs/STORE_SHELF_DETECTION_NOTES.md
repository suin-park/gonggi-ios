# 매대 기록: 중복 등록과 구조물 오등록 (원인, 수정, 근거)

관련 코드: `Gonggi/Features/StoreShelf/` 의 `Core/StoreRegistration.swift`, `Core/StoreRegionFilter.swift`,
`Core/StoreProductNaming.swift`, `Core/StoreSearchSession.swift`, `Platform/ShelfRecordingEngine.swift`.

## 1. 확인한 원인 (코드와 빌드 95 검토 화면으로 확인, 기기 자료로는 아직 확인 못 함)

| 항목 | 빌드 95의 동작 | 판단 |
|---|---|---|
| 프레임마다 새 ID | 제품 ID는 기록을 끝낸 뒤에만 만들어진다(`buildDraft`). 프레임마다 ID가 생기는 경로는 없다. | 원인 아님 |
| 같은 제품이 여러 후보로 갈라짐 | 관측을 "평면 위 위치가 가까운가"로만 묶었다. 냉장고처럼 제품이 매대 앞면보다 안쪽에 있으면 카메라가 움직일 때 평면에 투영한 위치가 시차만큼 흔들려서(깊이 0.4 m, 시선각 ±0.5이면 ±0.2 m) 반경(약 0.06 m)을 벗어나 새 후보가 된다. 또 새 관측은 가장 선명한 한 장하고만 외형을 비교해서, 각도가 달라지면 0.20을 넘어 다시 갈라졌다. | **원인 (시뮬레이션으로 재현)** |
| 한 제품의 일부를 별개 제품으로 검출 | 라벨 박스와 병 전체 박스가 둘 다 NMS를 통과했다(포함 비율 0.85 미만). | 원인(코드상). 발생 빈도는 미확인 |
| 구조물을 제품으로 검출 | 범용 사각형 + 전경 검출은 선반 칸, 문틀, 조명 띠도 반환한다. 크기 제한이 0.02~0.9 m로 느슨하고 형태/질감 검사가 없었다. 검토 화면의 제품 6(흰 띠), 제품 9(검은 세로 띠), 제품 8(선반 칸 전체), 제품 7(캔 + 배경)이 이에 해당한다. | **원인 (화면으로 확인)** |
| 위치/좌표 변환 오류 | 위치는 평면 교차 + 거리 불확실성 계산으로 이전 검증을 통과했다. 안쪽 깊이 보정만 빠져 있었다. | 깊이 보정 추가. 좌표 변환 자체의 오류는 발견하지 못함 |
| 병합과 변종 분리 | 같음 0.20, 비슷함 0.35는 미보정 값이다. 구조물이 많은 화면에서는 모든 항목에 "비슷한 포장" 경고가 붙었다(검토 화면). | 임계값을 올리지 않고 근거를 추가했다(아래) |
| 저장하지 못한 영역 62곳 | 약한 조각(관측 3회 미만, 흐림)을 클러스터마다 1곳으로 세었다. 위 파편화가 그대로 영역 수가 됐다. | 같은 자리 영역은 1곳, 이미 등록된 제품의 조각은 제외 |

## 2. 수정

1. **구조물/비제품 거부** (`ShelfRegionFilter`): 물리 크기(폭 0.03~0.45 m, 높이 0.04~0.55 m), 형태(긴 변/짧은 변 5.5 초과), 질감(밝기 표준편차 12 미만)으로 거부한다. 카탈로그를 보지 않고 구조 근거만 쓴다.
2. **같은 프레임 안의 포함 관계** (`ShelfRegionArbiter`): 제품 둘 이상을 담은 큰 박스(선반 칸)와 더 큰 제품 안의 작은 박스(라벨)를 버린다.
3. **시차 인식 추적** (`ShelfObservationAggregator`): 위치 일치 판정에서 매대 앞면 뒤 0~0.6 m 깊이를 허용하고, 여러 시점에서 깊이를 맞춰 실제 위치와 깊이를 추정한다. 새 관측은 최근/선명 관측 여러 장과 비교한다. 같은 프레임의 두 검출은 합치지 않는다. 기록 종료 시 겹치지 않고 같은 자리, 같은 외형인 후보를 합친다. 같은 외형이라도 위치가 멀면 합치지 않고, 같은 제품이 여러 곳이면 한 제품의 여러 위치로 남는다.
4. **제품 단위 묶음** (`ShelfProductGrouper`): 외형 거리에 더해 바코드(같으면 같은 제품, 다르면 다른 제품)와 확실히 읽은 이름(다르면 다른 제품)을 쓴다. 임계값은 그대로다.
5. **대표 사진**: 선명도 x 온전함(이미지 경계에서 잘리지 않음)으로 고른다.
6. **제품명 자동 저장** (`ShelfTextReader`, `ShelfProductNameExtractor`): 선명한 관측에서 한글+영문 OCR을 읽고(이 기기와 revision에서 지원되는 언어만, 결과는 진단에 기록), 2회 이상 읽힌 줄만 이름으로 쓴다. 영양성분, 유통기한, 광고 문구, 고객센터 문구, 가격은 제외한다. 읽지 못하면 "제품 N"을 유지하고 확인을 요청한다. 직접 입력한 이름은 덮어쓰지 않는다.
7. **제품 찾기**: 카메라를 비추면 자동 검출 → 비교 → 6프레임 중 4번 일치(다른 결과는 1번 이하)일 때 한 번만 확정 → 안내 시작. 안내 중에는 인식을 멈추고(다른 제품이 보여도 대상이 바뀌지 않음), 「안내 끝내고 다른 제품 찾기」로 끝낸다. 불확실할 때만 후보를 보여주고, 포장에서 읽은 글자가 후보 중 정확히 하나의 이름과 같을 때만 확정한다. 미등록은 가장 비슷한 제품으로 확정하지 않는다.

## 3. 검증 범위

- **Linux 순수 로직 테스트(98개)**: 시뮬레이션 기하(깊이 0.4 m, 8시점)로 한 제품이 한 후보로 묶이고 위치/깊이가 복원되는지, 깊이 처리를 끄면 갈라지는지, 이웃한 두 제품이 분리되는지, 한 프레임의 동일 외형 두 검출이 분리되는지, 이름 추출(한글/영문/혼합/노이즈), 이름 보호, 검색 세션 상태 전이.
- **측정하지 않은 것**: 실제 사진에서의 검출 정확도, 중복률, OCR 정확도, 인식 속도, 인식부터 안내까지의 시간. 실제 냉장고 촬영에서 위 수치를 아직 모른다.
- 검출 자체는 여전히 범용 사각형 + 전경 검출이다(전용 상품 검출 모델이 없다). 이번 수정은 그 결과를 거르고 묶는 단계를 보강한 것이다.
