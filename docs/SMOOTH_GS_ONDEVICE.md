# 매끈한 표면 3DGS — 촬영 후 기기 내 처리 (실험)

실험 › 실시간 제품 3DGS › **매끈한 표면 만들기 (저장한 제품)**
실험 › 실시간 공간 생성 › **매끈한 표면 만들기 (저장한 공간)**

'연구 기록'을 켜고 저장한 결과(.kmogs + .kmoreplay)를 읽어, PC 연구(fur_surface_study)의 최종안
**매끈한 표면(2DGS식 법선 일치) + shtvpc(방향별 색·노출·색 평활·포즈 재보정·시야 원뿔)** 를 기기에서 만든다.
서버를 쓰지 않는다. 원본 저장본은 바꾸지 않는다. 기록하기의 외부 GPU 생성 경로와 무관하다.

## 단계 (PC 스크립트 대응)

| 앱 단계 | PC | 기본값 |
|---|---|---|
| 0 사진·지도 읽기 | gtlib.Photos | 지도와 같은 세그먼트의 사진만 |
| 1 포즈·지도 맞춤 | posejoint.py JOINT | 3라운드 × (사진별 포즈 LM 320폭 8회 → 지도 2000회) |
| 2 표면 만들기 | prep_start.py | TSDF 4 mm(공간 1 cm), 원반 60,000개 목표 |
| 3 매끈한 표면 학습 | normal_fit.py nc | 6000회, λ 0.05(1500회부터) |
| 4 포즈 다시 맞춤·준비 | appear_fit.py shtvpc 앞부분 | 포즈 LM 8회, 시야 원뿔, 이웃 6개, λ_TV 보정(20장) |
| 5 화질 보정 학습 | appear_fit.py shtvpc | 3000회 |
| 6 저장 | — | Documents/smooth-gs |

학습 해상도: 기본 **재생 기록 원본 최대 폭**(설정에서 1920 / 960 / 640 선택). PC 검증은 640×480뿐이다.
배경 팽창(31×31)·침식(5×5) 반경은 학습 폭 / 640에 비례해 키운다. 원반 수·반복 수는 해상도와 무관하게 PC 값이다.

## PC와 다른 점 (의도한 차이, 미검증)
- 표면: Open3D 메시 + Taubin 10 + 포아송 디스크 → 블록 TSDF(같은 갱신식) 0 교차점 + 기울기 법선 + 이웃 법선 평균 + 격자 균등 표본. 간격 = √(추정 면적/원반 수).
- 시작 원반 관측·방향·색: 메시 광선 → 시작 원반을 직접 렌더한 깊이(허용 6 mm, 공간 1.5 복셀).
- 포즈 맞춤 라운드: 누적 보정량 대신 현재 포즈 기준 보정량(목적 함수 같음). posejoint의 BASE 지도(비교용)는 만들지 않는다.
- 보류(held-out) 없이 모든 사진으로 학습한다. 순서 섞기 난수는 numpy와 다르다.
- 법선 손실 gradient: torch autograd → 해석식(PC에서 torch와 상대 오차 3e-6 일치 확인, 앱 시험에서 유한차분 확인).

## 시간 기록
결과마다 `.timing.json`과 `.summary.txt`: 단계별 초, 반복당 ms(p50/p95), 계산별 누적 초(decode, targets, colour, forward, loss,
normal_raster, normal_loss, backward, backward_normal, tv, adam, pose, tsdf_*, surface_*), 열 상태 변화, 열 때문에 쉰 시간, 메모리 최고값.
학습 사진이 메모리 예산(700 MB)을 넘으면 매번 JPEG에서 다시 풀며 그 시간은 decode에 들어간다.
1~3단계 결과는 `.work/`에 남아 같은 설정이면 이어서 한다(이어 쓴 단계는 기록에 표시).

## 보기
CPU 렌더(GSORaster, display 규칙)로 매끈한 표면 / 원래 3DGS / 반반을 같은 카메라로 돌려 본다. 노출은 항등, 방향별 색은 시야 원뿔 안으로 제한.
PLY는 c0 색만 담는다(방향별 색·원뿔은 .kmsgs에만).

## 알려진 한계
- A15 시간·열·메모리, 원본 해상도·공간에서의 화질은 측정 전이다. 계산은 모두 CPU다(Metal backward 없음).
