# 실시간 공간 생성 (실험) — 구현 설명

위치: 기록하기 → 맨 아래 **실험 → 실시간 공간 생성**. TestFlight 3.0(18)부터. 기존 센서 검사 메뉴는 그대로 있다.

이 기능은 **iPhone 14 Plus 한 대에서, 서버·LiDAR 없이, 카메라로 비추는 동안 색이 있는 3D 가우시안 표면을 쌓고 다른 시점에서 둘러보는 것**을 확인하기 위한 실험 빌드다.
품질·속도는 아직 실기기에서 측정되지 않았다. 아래 목표값(30fps, 반영 p95 500ms)은 **목표**이며 달성했다는 뜻이 아니다.

## 흐름

```
ARKit 단일 세션 (30fps 4:3 포맷)
 → 같은 ARFrame의 영상·포즈·K·timestamp를 소유한 작은 복사본(RTFrame)으로 묶음
 → 키프레임 선택 (새 시점·선명도·속도)
 → 시간차 스테레오 (참조 키프레임 최대 2장, 역깊이 평면 스윕)   ┐ 깊이 증거
 → (선택) Core ML 단안 깊이 → 스테레오 점으로 1/Z=a·m+b 정렬 → 임시 깊이 ┘
 → 표면 가우시안 생성 (법선, 접선 기저, 표본 간격 기반 크기)
 → 지도 융합 (병합 / 이중 벽 거부 / 새로 추가) → 가림 위반 제거 → 가지치기·상한
 → 정밀화 (노출 보정, 고해상도 색, 법선 정리)
 → 렌더용 배열 게시 → Metal 가우시안 렌더 (공분산 투영, 깊이 정렬, 알파 합성)
 → 종료 시 PLY 저장 → 다시 열어 둘러보기
```

## 알고리즘 요약

| 단계 | 내용 | 파일 |
|---|---|---|
| 좌표 | ARKit 카메라(앞=-z) → CV 카메라(앞=+z)는 `diag(1,-1,-1)`. 깊이는 **camera-Z**이며 range와 구분. K는 픽셀 중심 규약으로 축소·크롭 변환 | `Core/RTMath.swift` |
| 프레임 | 420 bi-planar → RGB 640폭/320폭 복사. ARFrame을 쥐지 않음. 대기 작업은 1개(최신만 유지, 오래된 것은 버림) | `Core/RTFrame.swift`, `Engine/RTEngine.swift` |
| 키프레임 | 간격 0.18s, 이동 4cm 또는 회전 7°, 속도 상한(번짐), 추적 normal, 선명도 | `RTKeyframePolicy` |
| 스테레오 | 320폭 영상, 2픽셀 간격 표본, 5×5(9점) ZNCC, 역깊이 간격 ≈0.7px 시차, 경계에서 끝나면 범위 확대(0.15~15m), 포물선+1/4 간격 세부 탐색, 모호성·비용·시차각·지지 검사. 이동이 없으면 `noBaseline`으로 증거 없음 | `Depth/RTStereo.swift` |
| 단안 사전값 | Depth Anything V2 Small F16(Apache-2.0, SHA-256 고정). CPU+Neural Engine. 상대 역깊이를 스테레오 점에 RANSAC+최소제곱으로 정렬. 정렬 실패 시 2초까지 직전 정렬을 이어 쓰고, 스테레오와 크게 충돌하는 약한 점은 제거. 모델이 없으면 스테레오 전용 | `Depth/RTMono.swift` |
| 가우시안 생성 | 이웃 표본 3D 점으로 법선, 깊이 불연속은 법선에 사용 안 함, 시선과 거의 평행(cos<0.2)은 거부. 크기 = 0.85×표본 간격, 기울기 방향 1/cosθ, 법선 방향은 얇게 | `Map/RTSurfaceBuilder.swift` |
| 지도 | 위치·법선·접선·색·불투명도·크기. 공간 해시(6cm 칸). 임시 vs 확인됨(서로 다른 위치 4cm 이상에서 스테레오 2회 이상 지지). 같은 위치 반복 관측은 확인 증거로 세지 않음. 같은 키프레임 표본끼리는 병합하지 않음 | `Map/RTGaussianMap.swift` |
| 이중 벽 | 병합 후보가 없으면 법선 방향으로 tolN~3.5·tolN 거리의 평행 표면을 탐침. 확인된 표면이면 새 표본 거부, 임시면 교체 | 같은 파일 |
| 떠다니는 것 | 확인된 스테레오 깊이보다 분명히 앞에 있는 가우시안은 3번 위반 시 제거(관측 6회 미만) | `carve` |
| 추적 단절 | 1초 이상 비정상 후 복귀, 프레임 간격 1.5초, 포즈 점프 0.6m, 재개 → 새 **세그먼트**. 세그먼트 사이는 병합·가림 제거를 하지 않음 | `RTEngine` |
| 정밀화 | 노출 gain(안정 가우시안의 밝기 비 중앙값), 640폭 영상에서 색 재샘플(정면일수록 가중), 이웃 평면 맞춤으로 법선 정리. 끄고 켜서 비교 가능. 위치·불투명도 학습은 하지 않음 | `Map/RTRefiner.swift` |
| 렌더 | 인스턴스 쿼드, 정점 셰이더에서 `Σ2D=J W Σw Wᵀ Jᵀ`, 고유분해로 타원 축, 프래그먼트 가우시안 감쇠, 먼 것→가까운 것 알파 합성(미리 곱한 알파). 깊이 계수 정렬(8192 구간), 예산 초과 시 먼 구간부터 버림 | `Render/*` |
| 저장 | 표준 3DGS PLY(binary): x y z nx ny nz f_dc_0..2 opacity(logit) scale_0..2(log) rot_0..3. 메타 JSON·요약 텍스트 동봉. 같은 PLY를 앱에서 다시 열어 둘러봄 | `Map/RTPLY.swift` |

## 자원 상한과 거버너
- 가우시안 수 상한 30만(압박 시 60%), 렌더 예산 22만(GPU p95>28ms면 20% 감소, 여유 있으면 증가), 키프레임 링 8장(약 10MB), 대기 작업 1개.
- 열 `fair`: 단안 간격 2배. `serious` 또는 메모리 1.9GB: 단안·정밀화 끔, 상한 감소. `critical` 또는 2.4GB: 자동 종료·저장.
- 시작·종료·화면 닫기·백그라운드: ARKit 세션 정지, 처리 대기열 비움, 저장.

## 사용
1. **시작** → 천천히 **옆으로 이동**하며 비춘다(제자리 회전만으로는 깊이를 알 수 없고, 앱이 안내 문구를 띄운다).
2. 기본은 **가우시안만 보기**. 토글로 카메라 영상을 어둡게 깔 수 있다. 정밀화·임시 가우시안 주황색 표시도 토글.
3. **일시정지·둘러보기**: 카메라를 놓고 가상 시점으로 탐색(한 손가락 회전, 두 손가락 이동, 핀치 확대, 두 번 탭 처음 시점). **이어서 스캔**으로 새 세그먼트로 재개.
4. **종료·저장** → PLY, 메타, 요약, JSONL을 만들고 공유 시트로 보낼 수 있다. **저장한 결과**에서 다시 열 수 있다.

## 로그 (실험 결과에서도 보임)
`rt_start`(설정, 코드 SHA, 모델), `rt_kf`(키프레임별 단계 시간·개수·거부 사유·재사용·병합 오차), `rt_hb`(1초: ARKit Hz, 키프레임 Hz, 지연 p50/p95, 대기열, 가우시안 수, 렌더 fps/CPU/GPU, 메모리, 열), `rt_segment`, `rt_tracking`, `rt_governor`, `rt_mono_load`, 요약.

## 측정되지 않은 것 (실기기 필요)
- 키프레임 처리 지연과 새 표면 반영 지연 p95, 30fps 표시 유지, 5분 연속 실행의 열·메모리.
- 벽 이중화·구멍·얇은 구조의 실제 발생률, 다른 시점의 PSNR/SSIM, 깊이 정확도(표적 거리 비교).
- 단안 모델의 Neural Engine 실행 여부와 A15에서의 지연.
- 정밀화 켬/끔의 실제 효과 차이(로그의 `photoDiff`, `mergeResidualCm`으로 비교).
- 세그먼트 사이의 좌표 정합(구현하지 않음; 세그먼트는 별개 좌표계로 취급).

## 알려진 한계
- 첫 가우시안은 이동량 약 4cm 이후에 나타난다(스테레오 증거가 생길 때까지). 시작 직후 단안만으로 임시 표면을 만들지 않는다.
- 위치·불투명도의 경사 학습(완전한 3DGS 최적화)은 없다. 정밀화는 색·노출·법선에 한정된다.
- 저장된 PLY는 임시/확인됨 구분과 세그먼트 경계를 담지 않는다.
- 렌더는 정렬 근사(깊이 구간 계수 정렬)이며 같은 구간 안에서는 순서가 보장되지 않는다.

## 3.0(19) 지도 안정성·형상 품질 수정

### 3.0(18) 실기기 한 번의 실행에서 측정된 값 (iPhone 14 Plus, 세그먼트 1, 정밀화 켬, 단안 켬)
이전의 "전부 미측정"을 아래 값으로 바꾼다. **한 번의 실행에서 받은 처리 성능**이며, 실제 기하 정확도(실측 거리 대비 오차)와 장시간 성능을 뜻하지 않는다.

| 항목 | 값 |
| --- | --- |
| 키프레임 → 지도 반영 지연 | p50 120 ms / p95 195 ms |
| 지도 변경 → 렌더 배열 게시 지연(publish) | p50 322 ms / p95 562 ms (화면 표시 지연이 아님) |
| 스테레오 단계 | p50 32 ms / p95 46 ms |
| 렌더 | 30 fps, GPU p95 19.4 ms |
| 메모리 피크 | 678 MB |
| 최종 가우시안 | 140,664 (확인 106,334 / 임시 34,330) |
| 누적 | 추가 1,103,897 · 병합 1,318,732 · 교체 101,671 · 가지치기 875,112 · 자유공간/상한 제거 88,121 |
| 스테레오 유효 격자 비율 | 21% |
| 단안 채움 | 1,260,049 점 |
| 노출 이득 | 1.40 (상한에 고정) |

- 병합 잔차는 같은 표면 후보 사이의 법선 방향 차이이며 실제 거리 오차가 아니다.
- 스테레오 비용만이 병목이 아니다. 지도 생애주기(추가/가지치기 반복)와 품질이 우선 과제다.
- PLY는 최종 형상의 증거, summary는 집계값이다. JSONL에는 영상·깊이 표본이 없어 융합 과정을 재생할 수 없다.

### 확인된 원인과 수정
| 구분 | 내용 |
| --- | --- |
| A | `mergeInto`가 `pos`만 옮기고 `cell`/해시 연결을 갱신하지 않았음 → `relink()`로 옛 연결을 한 번 떼고 새 칸에 한 번만 건다. `validateIndex()`로 검증 |
| B | 한 키프레임에서 여러 후보가 한 가우시안을 연속 갱신하고 `hits`에 중복 → 가우시안별로 모아 한 번만 갱신, hits 중복 제거 |
| C | 단안 관측이 검증된 가우시안의 위치·색을 움직임 → 상태별 갱신 권한(임시/후보/안정)과 관측 등급(0 단안, 1 스테레오 약함·지도 도움, 2 강함) |
| D | 정밀화가 가림 검사 없이 색을 다시 읽고, 노출 이득이 방금 갱신한 색으로 추정됨 → 가시성(깊이 일치) 검사, 이득은 갱신 전 저장 색과 같은 표면 짝으로 추정 |

### 가설(실기기 A/B 전까지 확정 아님)
- 이득 1.40 고정이 실제 노출 변화인지 되먹임 인공물인지: 새 추정기는 `gainRaw`를 기록하므로 다음 실행에서 구분할 수 있다.
- 털/번짐은 기울어진 면의 늘어난 타원, 단안 임시 가우시안, 먼 거리 깊이 잡음에서 온다고 보지만 PLY 통계와 화면 관찰에 근거한 추정이다.

### 상태 관리
- 임시: 자유롭게 갱신·교체·만료. 단안 임시는 키프레임당(2500)과 총량(30,000) 예산, 만료 6 키프레임.
- 후보: 서로 다른 위치(기선 ≥ 4 cm)에서 독립 스테레오 지지 2회 이상. 제한된 갱신.
- 안정: 지지 4회 이상, 기선 ≥ 8 cm, 시선 각도 차 ≥ 5°, 잔차·누적 이동량 한계 안. 위치·법선·크기·색은 기본 유지하고 훨씬 가까이서(15% 이상) 정면으로 본 강한 스테레오로만 소폭 갱신.
- 모순: 안정/후보 표면과 어긋나는 강한 스테레오 관측은 별도 후보로 쌓고, 서로 다른 키프레임 3회가 같은 오프셋에 모이면 그 가우시안만 새 위치로 옮기고 후보로 강등해 다시 검증한다.
- 관측되지 않았거나 가려졌다는 이유로 후보·안정 표면을 지우지 않는다. 제거는 확인된 스테레오 깊이가 자유 공간임을 반복해서 보일 때, 임시 만료, 상한뿐이며 사유별로 `removed_*` 이벤트로 센다.

### 재방문
- `RTMapPrediction`이 후보·안정 가우시안을 현재 시점에 투영해 깊이 예측을 만들고, 스테레오 탐색의 사전값(힌트)으로만 쓴다. 지도의 도움을 받은 깊이는 독립 증거가 아니다(신뢰도 상한 0.6, 갱신 가중치 낮음, 모순 증거에서 제외).
- 지도가 설명하지 못하는 영역만 새로 추가한다.
- 일시정지 후 재개 시 새 세그먼트의 스테레오 깊이가 이전 지도 예측과 여러 키프레임에서 충분히(≥70%) 일치할 때만 같은 좌표계로 합친다. 아니면 별개 세그먼트로 유지한다(강제로 합치지 않음). 실기기 데이터는 세그먼트 1개였으므로 이 경로는 실기기에서 검증되지 않았다.

### 형상
- 접선 크기 상한 3.5 cm(기울기 방향 5.25 cm), 늘림 상한 2.5배, 생성 최대 깊이 6 m, 깊이 불확실성 σZ/Z > 6% 거부, 평면 잔차가 큰 단안 표본 거부, 단안은 2×2 격자 중 하나. 일괄 축소·흐림은 하지 않고 믿을 수 없는 표본은 구멍으로 남겨 재관측에 맡긴다.

### 저장·공유
- `space-<runId>.ply` + `.state`(가우시안 id, 상태, 관측 수, 세그먼트 등; PLY 체크섬으로 연결) + `.meta.json`(runId, logFile) + `.summary.txt` + 같은 runId의 JSONL을 한 번에 공유한다. 저장 직후와 다시 연 뒤 모두 같다.
- 상태 파일이 없거나 체크섬/개수가 다르면 모든 점을 "상태 미확인"으로 연다(전부 검증됨으로 보지 않는다). 로그가 없으면 없다고 표시한다.
