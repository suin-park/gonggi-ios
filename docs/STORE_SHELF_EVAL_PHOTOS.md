# 실제 매대 사진 평가 자료 준비 (제품 검출과 인식 성능 측정용)

이 자료가 없으면 검출률, 오검출, 제품/변종 구분, 미등록 판정은 **측정되지 않는다**(테스트는 건너뜀으로 보고된다).

## 1. 무엇을 찍는가
| 구분 | 용도 | 장수 | 내용 |
|---|---|---|---|
| `register` (등록 촬영) | 관리자가 매대를 등록하는 상황 | 3~5장 | 서로 다른 제품 **20개 이상**이 보이는 매대 구도. 맛/용량 변종 3쌍 이상 포함 |
| `search` (검색 촬영) | 고객이 나중에 다시 찍는 상황 | 3~5장 | **다른 날/다른 각도**로 새로 찍은 사진. 등록 사진의 일부를 잘라 쓰지 않는다. 등록하지 않을 제품 5개 이상을 같이 둔다 |

- 같은 장면의 같은 프레임을 양쪽에 쓰지 않는다(앱 테스트가 파일 해시가 같으면 실패 처리한다).
- 구도: 매대 정면, 선반 1~3칸이 한 장에 들어오게, 제품 하나가 화면 높이의 1/6 이상. 실제 매장 조명. 가격표와 선반 프레임이 보여야 한다(오검출 평가).
- 휴대폰 세로 사진 그대로 괜찮다. 도구가 EXIF 회전을 적용해 저장한다.

## 2. 정답 만들기 (정답 박스와 제품 ID)
```
pip install opencv-python pillow
python tools/shelf_labeler.py --in <사진 폴더> --out GonggiTests/Fixtures/ShelfPhotos --role register --split tune
python tools/shelf_labeler.py --in <사진 폴더> --out GonggiTests/Fixtures/ShelfPhotos --role search   --split eval
```
- 제품 하나당 박스 하나를 드래그하고(Enter), 제품 ID를 입력한다. 등록 사진과 검색 사진에서 **같은 제품은 같은 ID**.
- 등록하지 않는 제품은 ID를 비운다(`-`). 가격표, 프레임, 포장 무늬에는 박스를 그리지 않는다.
- `--split tune`: 임계값을 맞추는 데 쓸 수 있는 자료. `--split eval`: 최종 평가 자료이며 **임계값 조정에 쓰지 않는다**.
  권장: 등록/검색 촬영 중 절반씩 tune, 나머지 eval.

## 3. 어떻게 제출하는가
- 만들어진 `GonggiTests/Fixtures/ShelfPhotos/` 폴더(JPG + JSON)를 저장소 밖 경로로 전달해 주시면 된다(사진에 매장 정보나 얼굴이 있으면 제외).
- 개발자는 이 폴더를 테스트 번들에 넣고 CI에서 `ShelfRecognitionFixtureTests`를 실행해 아래를 출력한다.
  - `SHELF_DETECTION_TOTAL`: 검출률, 정밀도(오검출), 합치거나 나눈 비율 (split별)
  - `SHELF_RECOGNITION_TOTAL`: top1 정확도, 후보에 정답 포함 비율, 잘못된 확정(변종 혼동 포함), 미등록 오인식, 불확실 비율
  - `SHELF_THRESHOLD_SUGGESTION`: tune split에서 계산한 임계값 제안(같은 제품 대 다른 제품 거리 분리 여부)
- 검출 실패와 특징 비교 실패는 구분해 보고된다: 검출은 사진 전체에서 박스를 찾는 단계, 인식은 **정답 박스**로 자른 이미지를 비교하는 단계다.

## 4. 판정 기준 (결과를 보기 전에 고정)
| 항목 | 기준 |
|---|---|
| 검출률 | ≥ 0.80 |
| 정밀도 | ≥ 0.70 |
| 잘못 합치거나 나눈 비율 | ≤ 0.15 |
| 등록 제품 top1 | ≥ 0.80 (후보 포함 도달률 ≥ 0.90) |
| 잘못된 확정 비율 | ≤ 0.05 |
| 미등록 제품이 기존 제품으로 확정된 비율 | ≤ 0.05 |
- 기준에 못 미치면 원인에 따라 검출기(`ShelfProductDetector`) 또는 특징 추출(`ShelfAppearanceExtractor`)을 교체한다. 교체 후보와 라이선스는 문서 `STORE_SHELF_TWO_DEVICE_TRIAL.md`의 7절을 따른다.
