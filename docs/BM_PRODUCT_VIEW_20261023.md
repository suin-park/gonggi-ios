# 제품 Bm 보기 (내부 TestFlight 빌드 3.0 (29)) — 구현 범위와 확인 방법

작성: 2026-10-23. 브랜치 `feat/product-bm-view`. PC 연구(research/gs_ref)의 Bm을 앱(Swift)에 옮긴 것이다. **PC 연구 결과가 앱에 이미 있다고 가정하지 않고** 아래 표의 항목만 구현·시험했다.

## 1. PC에만 있던 것 vs 이번에 앱에 들어간 것

| 항목 | 이번 빌드 | 근거(코드) | 시험 |
|---|---|---|---|

| 지도 깊이(보정 포즈에서 렌더, 알파>0.5, 마스크 15px 확장) | 앱에 구현 | `BmEngine.prepare` | 깊이 ≈ 평면 1 m, 마스크 밖 누출 < 20% |

## 2. 사용 흐름
1. **기록하기 › 실험 › 제품 Bm 보기 (저장한 결과)**
2. 목록에서 저장한 제품 결과를 고른다(재생 자료가 있는 결과만 Bm 가능). 다른 곳에서 받은 파일은 같은 화면의 **저장본 파일 가져오기**로 `.kmogs` + `.kmoreplay`를 함께 선택해 가져온다.
3. 열면 지도를 읽고 → 사진을 읽고 → 첫 화면에 쓸 사진 6장(포즈 보정·깊이·가장자리 레이어)을 준비한 뒤 첫 화면을 그린다(취소 가능). 이후 남은 사진은 백그라운드로 준비하고, 사용자가 만지는 동안에는 멈춘다.
4. **보기 전환**: Bm / 3DGS / 반반(왼쪽 3DGS, 오른쪽 Bm). 전환해도 카메라가 같다.
5. **조작**: 한 손가락 회전, 두 손가락 이동(위아래·좌우), 핀치 확대, 두 번 탭 처음 시점. 슬라이더: 거리(접근·후퇴), 확대. 조작 중에는 320×240 미리보기, 멈추면 640×480(표준) 또는 고품질(내부 3배 격자)로 다시 그린다.
6. 닫거나 앱을 다시 열어도 같은 저장본에서 다시 열 수 있고, 포즈 보정·마지막 시점·모드는 `<저장본>.bm.json`에 저장돼 복원된다.

## 3. 새 촬영
기록하기 › 실험 › **실시간 제품 3DGS (기기 내)** — '연구 기록'이 켜진 상태(기본)로 촬영·저장하면 재생 자료(.kmoreplay)가 함께 저장되어 위 목록에 나타난다.

## 4. 진단 저장·공유
- Bm 화면 맨 아래 **현재 화면과 측정 로그 저장** → 공유. 로그(`<저장본>.bm-log.json`)에는 첫 화면 시간, 사진별 준비 단계 시간, 프레임 시간(p50/p95), 메모리, 열 상태, 설정이 들어간다(사진·지도 내용 없음).
- PC 대조용 단계 내보내기(기본 꺼짐): 실시간 제품 3DGS 화면의 **같은 입력으로 제품 비교** 시트 → "단계 1회 내보내기". 저장한 재생 기록을 실제 Swift 엔진에 넣어 8번째 비평가 키프레임 근처에서 **전체 화면 갱신 1회 + 원본 창 갱신 1회**의 학습 RGB·마스크·카메라·창 좌표, 갱신 전후 지도(+ Adam 모멘트·단계 수·경계 기준), 손실, 기울기, 설정을 `diag-step-*` 폴더에 쓴다. 학습 사진이 들어 있으므로 기기 안에만 저장되고 직접 공유할 때만 나간다. 형식은 `manifest.json`과 `GSOStepExport.dumpMap` 주석.

## 5. 한계(이번 빌드가 해결했다고 말하지 않는 것)
- 털·솜 질감과 흐림이 해결된 것이 아니다. 지도 자체(3DGS)는 이전 빌드와 같고, Bm은 그 지도의 깊이로 원본 사진을 재투영해 섞는 별도 보기다.
- A15 속도·메모리·발열은 측정 전이다. PC 시간으로 예측하지 않았다. 첫 화면 시간, 프레임 시간, 메모리, 열 상태는 로그에 남는다.
- 사진이 6장 미만이거나 제품 마스크가 없으면(공간 모드 기록) Bm을 만들 수 없고 3DGS만 보인다(원인 안내 표시).
- 3배 확대 보간, 최근접 색 채움은 PC와 구현이 다르다(위 표).
- CI·업로드 성공은 A15 실기기 검증 완료가 아니다.
