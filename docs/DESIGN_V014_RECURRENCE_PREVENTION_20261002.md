# V1_014 재발 방지 설계 (원인 검증 후) — 2026-10-02

상태: **설계안만**. GPU·운영 워커·TestFlight **변경 보류**.  
범위: 특정 의자(V1_014) 복구가 목표가 아니라, **유사 촬영에서 얇은 부품 누락을 예방·발견**하는 것.

### 운영 적용 게이트 (명시)
- **top-K / 다기준 선택 개선은**, 정확한 참조(원인 확인용 수동 표시 등)과 **개발에 쓰지 않은 검증 데이터**로 확인하기 **전까지 운영에 적용하지 않는다.**
- 수동 클릭 좌표는 **원인 확인용**이며 운영 규칙·촬영 UX에 넣지 않는다.

## 1. 큰 부분만 선택되고 얇은 부품이 빠지는 문제

### 최소 개선 (구현 가능, 의자 좌표 불필요)

**A. 선택 목적함수를 score-only에서 다기준으로 (CPU/실험 → 이후 운영)**  
후보 집합이 이미 있을 때(또는 multimask 출력 시):

1. **SAM score** (기존)
2. **박스/ hull 정합** (이미 있는 inside-box 계열)
3. **얇은 구조 보존 프록시 (보조 신호일 뿐)** — 제품 형상에 종속되지 않게:
   - 예: 마스크의 **세장 성분(elongated CC)** 존재 여부, 또는 hull 하단/측면 밴드 **채움율**
   - **주의**: 하부 채움율·세장 형태는 **보조 신호**이다. 박스 하부/측면을 바닥이 채운 것을 **부품 보존으로 계산하면 안 된다.** 반드시 **배경 혼입 프록시와 함께** 보거나, 혼입 가능성이 큰 밴드는 보존 점수에서 제외/감점한다.
   - 또는 stage2에서 **서로 다른 위치의 양성 포인트로 나온 후보들 간 IoU**가 낮으면 “큰 덩어리 하나”만 고르지 말고 **합집합/OR 후보**를 평가 집합에 포함
4. **배경 혼입 프록시** — hull 안이지만 저채도·고휘도 바닥 밴드 점유율 상한 (제품별 튜닝 상수로 두지 말고 soft penalty)

판정: `(부품 보존 프록시 ↑)` AND `(배경 혼입 프록시 ↓)` AND `(score가 극단적으로 낮지 않음)`.  
**면적↑ 또는 score↑만으로 승자 결정 금지.**  
**하부 채움↑만으로 부품 보존 pass 금지** (바닥 혼입과 구분되지 않으면 무효).

**B. stage1 early-exit 완화 (플래그, 실험 전용)**  
early-exit를 끄거나 임계를 올리고, 소수의 추가 프롬프트 후보를 평가 집합에 넣기.  
→ **정확한 참조 + 별도 검증 데이터로 확인하기 전까지 운영 미적용.**

**C. 후보 로그 보존 (개발·QA)**  
top-K 후보(score, area, 프록시)를 job 산출에 남김. 선택 로직 변경도 **운영 적용 전 검증 필수**.

### 남는 한계
- elongated / 하단 밴드 프록시는 형태에 따라 오탐·미탐.
- 잘못된 포인트(바닥)를 넣으면 혼입 증가.
- SAM이 후보를 안 내면(유형 **b**) 선택만으로는 불가 → 섹션 3.

## 2. 여러 사진에 보이는 부품이 마스크·학습에서 빠졌는지 검사

교차 뷰로 “의심”을 띄우되, **원인을 분리**한다:

| 코드 | 의미 | 근거 예 |
|------|------|---------|
| **mask_miss** | 사진에 부품이 **충분히 보이는데** 마스크/선택이 누락 | 인접 뷰에 하부·측면 실루엣이 있는데 해당 마스크만 급락; top-K에 보존 후보가 있었으나 score 패배(유형 c) |
| **capture_insufficient** | **촬영 자체가 부족**해 부품이 거의 안 보임 | 전 궤도에서 지지 구조가 프레임 밖·과다 가림·극단 클로즈업만; 박스 투영 하부가 이미지에 거의 없음 |

하부 채움율·세장 신호만으로 mask_miss로 단정하지 말 것 (바닥 채움과 혼동).

### 최소 개선

**D.** 인접 마스크 IoU/면적 급락 → 의심. 하부/측면 채움은 **보조**이며 floorLeakProxy가 높으면 `ambiguous_lower_fill` (채움≠부품). 궤도 전체에 구조 힌트가 없으면 `capture_insufficient`.  
**E.** 학습 후 지지면 공백이 반복될 때: 입력에도 구조가 보였으면 mask_miss 의심, 입력이 비었으면 capture_insufficient.

```
per_frame: { frameId, lowerBandCoverage, floorLeakProxy, selectedScore, class?: mask_miss|capture_insufficient|ambiguous }
job: { suspectFrames[], captureInsufficient?, crossViewDropFlags[] }
```

부품 보존·배경 혼입 **둘 다** 넣고, 하나만 좋아진 것을 pass로 쓰지 않음.

### 남는 한계
- 자동 검사는 의심이지 정답이 아님. 가림·블러는 경계가 흐림.

## 3. 자동 복구 불능 시 촬영 안내·불완전 결과 표시

**F. 예방 안내 (선택적, 제품 비종속)**  
지지대가 프레임 안에, 몸통+지지대가 같이 보이게. 특정 색/의자 형태 강제 금지.

**G. 실패·의심 시 — 원인 분기**  
1. **`capture_insufficient`에 근거가 있을 때만** 추가 촬영 안내 (낮음·옆·대각에서 지지 구조 실루엣).  
2. **mask_miss만** 있고 촬영은 충분하면 → 추가 촬영을 기본 처방으로 몰지 말고 **Incomplete 표시** (+ 향후 마스크/선택 실험).  
3. suspect가 있으면 완전 성공 UI 금지 (score·면적만으로 침묵 성공 금지).

### 남는 한계
- 자동 구분이 틀리면 CTA가 빗나갈 수 있음 → 보수적으로 Incomplete 우선.

## 한 줄 요약

재발 방지는 의자 좌표 외우기가 아니라, **선택 편향 완화(검증 전 운영 금지)**, **mask_miss vs capture_insufficient 구분**, **촬영 부족일 때만 추가 촬영**, **보존+혼입 동시 평가**이다. 범용 해결은 주장하지 않는다.
